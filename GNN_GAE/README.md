# 비정상 FE 메쉬 수리 (GNN_GAE)

상위 프로젝트(`../README.md`)는 메쉬 패치가 정상인지 비정상인지 **판정**한다.
여기서는 비정상으로 판정된 패치를 **정상으로 고친다**.

파싱·기하·그래프 변환·학습된 분류기는 상위 프로젝트 것을 그대로 재사용한다
(`src/gae_paths.py` 가 `../src` 를 sys.path 에 넣는다).

## 지금 상태 한 줄 요약

사람이 직접 고친 **수정 전/후 쌍 508건**으로 **재생성 모델**을 학습했다 (6절).
메쉬를 새로 그리지 않고 **"어느 절점을 어디에 합치고, 어느 삼각형 쌍을 사각형으로
합칠지"** 를 고른다. 사람 결과와 **정확히 같은** 메쉬를 학습 셋(90%) CV 에서 39.7%,
테스트(10%, 같은 결함은 학습 셋에 없음)에서 25.0% 만든다 — '연결만 변경' 은 둘 다 60%,
절점을 합치는 수정이 약하다. 심판 분류기 기준 비정상 판정은 80.5% → 28.1% (사람 22.4%).
화면(`app_regen.py`)에서 무엇을 지우고·만들고·옮겼는지 강조해 사람 결과와 나란히 본다.

## 3. 분류기가 사람 수정에 동의한다

학습에 이 메쉬들을 쓰지 않은 **심판 모델**(`../runs/train/deploy_10_14`)로 채점:

```
p(비정상) 중앙값   0.945 → 0.033
비정상 판정 비율    81.1% → 23.6%
p 가 내려간 쌍      96.9%
```

심판 자체 성능은 홀드아웃 AUC 0.9854 / ACC 0.9225 (학습 2,549 / 평가 284).
수정 쌍 원본 390개를 학습에서 뺀 대가로 F1 이 0.919 → 0.872 로 내려갔다.

## 4. 기하 지표로는 설명되지 않는다

```
삼각형 비율  0.221 → 0.163   (라벨 정상 메쉬는 0.044)
최대 skew    55.1° → 54.0°
불량각 요소   4개 → 2개
```

거의 안 움직이는데 p 는 0.945에서 0.033으로 무너진다. **사람은 삼각형을 줄이는 게
아니라 특정한 나쁜 국소 배치만 고친다.** (그래서 처음에 세운 "수리 = 삼각형 제거"
전제는 틀렸다 — 삼각형 비율 단일 피처의 라벨 AUC 0.914 는 상관이었지 메커니즘이 아니었다.)

`node_baseline.py` — 절점 주변 생김새 17가지로 "사람이 고친 자리" 를 맞히는 표 모델
(GNN 아님, 학습 403 / 채점 100 메쉬):

```
상위 3개 안에       90.0%
절점 단위 AUC      0.8841
```

가장 많이 쓰인 피처는 `aspect_max_adj`(주변이 얼마나 길쭉한가), `tri_frac_adj`,

반해 나머지는 67.2° / 22.5° / 0개다.

참고로 **분류기 어텐션만으로는 1순위 28.1%** 다 — 분류기는 "어디가 문제인지" 를
짚는 데는 약하고, "다 고쳐놓은 결과를 채점" 하는 데는 강하다. 둘은 다른 일이다.

## 6. 메쉬 재생성 (Bad → Good)

### 6.1 생성이 아니라 "편집 연산 고르기"

그래프 생성 모델로 메쉬를 통째로 다시 그리지 않는다 — 유효한 .bdf(1D 가 쉘 변 위,
비매니폴드 악화 없음)를 보장할 수 없고, 사람의 수정은 작고 국소적이다(2절). 대신
사람이 한 일을 **우리 편집 연산의 순서로 다시 쓸 수 있는지** 먼저 쟀다
(`regen_oracle.py` — 정답 대본을 뽑아 실제 연산 코드로 재현):

| 연산 | 사람 수정에서의 비중 |
|---|---|
| **절점 병합** `collapse_many` (이웃 절점에 합침) | 사라진 절점 481개 중 451개 |
| **삼각형 쌍 병합** `merge_tris` (삼각형 2개 → 사각형) | '연결만 변경'의 97%, 병합 뒤 남은 차이의 대부분 |

이 두 연산을 **1단계(절점 병합) → 2단계(삼각형 병합)** 순서로 적용하면 508쌍 중
**388쌍(76.4%)이 요소·1D·좌표까지 정확히 재현**된다. 이것이 이 연산 체계의 천장이다.
나머지 120쌍은 연산 밖의 수정이 섞였다:

| 재현 못 한 사유 | 쌍 |
|---|---:|
| 연산 밖 재배치 (삼각형+사각형 다시 나누기 12, 사각형 쪼개기 5, T자 절점 흡수 6 …) | 40 |
| 절점 추가 | 25 |
| 요소는 맞는데 1D 가 다름 | 18 |
| 순수 삭제 (이어받는 절점 없음) | 13 |
| 좌표 이동 | 11 |
| 연산이 거부 (두 칸 떨어진 병합 5 …) | 8 |
| 새 절점으로 교체 | 5 |

### 6.2 데이터 분할 — 10% 테스트, 같은 결함은 한쪽에만

`runs/regen_split.csv` 에 **한 번 만들어 고정**한다 (`regen_data.py`). 학습 456 / 테스트 52.
수정 종류로 층화하고, **같은 결함을 고친 쌍은 같은 쪽**에 둔다 — 패치들이 겹쳐서 508쌍 중
334쌍이 '지운 요소(좌표 기준)' 를 다른 쌍과 공유한다(한 결함이 최대 10개 패치에). 처음
무작위로 나눴을 때는 **테스트 51쌍 중 32쌍이 학습 셋에 같은 결함의 쌍둥이**를 두고 있었다.
지운 요소를 공유하거나 원본 요소가 50% 넘게 겹치는 쌍을 한 묶음(259묶음, 최대 10쌍)으로
보고 묶음 단위로 나눈다. 학습 셋 안의 5-fold 도 묶음 단위로 미리 적어 둔다.
(테스트 셋을 열기 전에 발견해 분할을 다시 만들었다. 그 전 실행은
`runs/_archive_leaky_split/` 에 남겨 두고 비교에 쓰지 않는다.)

### 6.3 모델

```
원본 ──1단계──▶ 중간 메쉬 ──2단계──▶ 재생성 결과
       절점 병합을 하나씩:              삼각형 쌍 후보(메쉬당 ~2개)에 점수,
       [후보 ~200개 + '멈춤'] 중         임계값 이상을 겹치지 않게 합친다
       최고를 골라 적용 → 다시 본다
```

- **후보** (`regen_feats.py`): 1단계는 변으로 이어진 이웃과 사각형 대각 모서리의 절점 쌍,
  **양방향**(어느 자리가 남느냐로 결과가 갈린다). 실제로 적용해 보고 거부되는 후보는 뺀다.
  사람이 한 병합의 95.6%, 삼각형 병합의 100%가 후보 안에 든다.
- **미리보기 피처**: 후보를 사본에 실제로 적용해 주변이 어떻게 바뀌는지(나쁜 요소 수,
  최소각, skew, 삼각형 수, 면적) 잰다. 사람이 고르는 기준이 그것이라서다.
- **1단계 채점기** = GNN. 부모의 요소기반 그래프에 **심판 분류기(`deploy_10_14`) 인코더를
  이어받아** 미세조정한다(그 모델은 이 508쌍의 원본을 학습에 안 썼다). 요소 임베딩을
  절점마다 모아(평균·최대) `[remove 절점, keep 절점, 피처]` 로 후보 점수를 내고, 메쉬
  임베딩으로 **'멈춤' 점수**를 낸다. 손실은 메쉬마다 [후보들, 멈춤] 위의 softmax(listwise).
  학습에는 원본과 함께 **사람의 병합을 일부 적용한 중간 상태**를 쓴다 — 남은 병합이 정답,
  다 적용한 상태의 정답은 멈춤이다.
- **2단계 채점기** = gradient boosting (피처만). 후보가 학습 셋 전체에 ~950개뿐이라
  GNN 보다 나았다 (1단계가 맞았을 때 2단계 완성률 85% vs 79%).

반복형 + 멈춤으로 바꾼 이유는 CV 를 쪼개 본 결과다: 한 번에 점수를 매기는 방식(oneshot)은
병합 2개짜리 메쉬에서 평균 1.4개만 골랐고(정확 17%), "병합이 필요한가" 를 임계값 하나로
가르지 못했다. 반복형은 2개짜리 25%, 3개 이상 24%(oneshot 5%)로 올렸다.

### 6.4 학습과 임계값 — 전부 학습 셋 안에서

`regen_train.py` 가 학습 셋을 묶음 단위 5-fold 로 나눠 각 메쉬를 **자기를 학습에 안 쓴
모델**로 재생성하고(out-of-fold), 사람 결과와 정확히 일치하는 비율이 가장 높은 임계값
두 개(1단계 '여유' = 최고 후보 점수 − 멈춤 점수, 2단계 확률)를 고른다. 테스트 셋은
`regen_eval.py` 가 처음이자 한 번 연다.

후보 7개 설정을 같은 fold 로 비교해 **CV 정확일치 최고**를 최종으로 정했다 (테스트를 보기
전에 정한 규칙):

| 설정 | CV 정확일치 | 재현 가능한 쌍 중 | 바뀐 요소 IoU |
|---|---:|---:|---:|
| gbm, oneshot | 34.9% | 45.0% | 0.531 |
| gbm, 반복형 | 38.4% | 49.3% | 0.590 |
| gnn, oneshot | 38.6% | 49.0% | 0.567 |
| gnn, 반복형 (이진분류) | 36.0% | 46.1% | 0.531 |
| gnn, 반복형 + 멈춤 | 39.0% | 50.4% | 0.583 |
| gnn, 반복형 + 멈춤 + 문맥피처 | 38.8% | 49.6% | 0.578 |
| **gnn 반복형 + 멈춤, 2단계 gbm** | **39.7%** | **51.0%** | 0.586 |

상위 설정들의 차이(38.4~39.7%)는 **잡음 안**이다 — 같은 설정·같은 씨앗을 두 번 돌려도
GPU 비결정성 때문에 CV 가 39.7% / 37.5% 로 갈렸다.

**배포 모델은 다시 학습하지 않고 fold 모델들의 평균**이다 (`--deploy ensemble`). 처음에는
CV 로 임계값을 고른 뒤 학습 셋 전부로 다시 학습했는데(refit), 테스트에서 절점삭제 메쉬의
병합을 평균 0.70개만 골랐다(CV 의 fold 모델은 1.14개, 정답 1.63개) — 31개 중 15개에서
아무것도 안 합쳤다. 테스트를 다시 쓰지 않고 학습 셋 안에서 중첩 CV 로 확인했다
(`regen_nested.py` — fold 하나씩 가짜 테스트로 떼고, 나머지로 임계값 선택 + refit/평균 비교):

| 배포 방식 | 가짜 테스트 456쌍 정확일치 | 메쉬당 병합 (정답 0.875) | fold 별 병합 수 |
|---|---:|---:|---|
| fold 모델 평균 | **39.5%** | 0.55 | 0.68 / 0.55 / 0.57 / 0.47 / 0.48 |
| 다시 학습 (refit) | 37.3% | 0.76 | 1.24 / 0.66 / 0.65 / 0.88 / **0.36** |

refit 은 임계값과 점수 눈금의 관계가 **fold 마다 크게 흔들린다** (어떤 fold 는 과하게, 어떤
fold 는 너무 적게 합친다). 평균은 조금 보수적이지만 안정적이다. 같은 메쉬끼리 비교하면
평균만 맞힌 것 25 / refit 만 맞힌 것 15. 중첩 추정(37~40%)이 그냥 CV(39.7%)와 비슷하므로
CV 에서 임계값을 고른 탓에 숫자가 크게 부풀지는 않았다. 최종 모델은 여기에 **씨앗 3개**를
더해 fold 5 × 씨앗 3 = 15개 모델의 평균이다 (`--seeds 0,1,2`).

| 불변식 위반 메쉬 | 0% | 0% |
| 심판 비정상 판정 원본 → 재생성 (사람) | 80.5% → 28.1% (22.4%) | 86.5% → 50.0% (34.6%) |
| 불량각 요소 합 원본 → 재생성 (사람) | 1897 → 1346 (1297) | 327 → 254 (237) |
| 기록 재적용 = 결과 / .bdf 다시 읽기 = 결과 | 100% / — | 100% / 100% |
| 기준선: 변경 없음 / 상한(정답 대본) | 0.9% / 76.5% | 0% / 75.0% |

**어느 숫자를 믿을까 — CV 다.** 테스트는 52쌍이지만 같은 결함을 고친 쌍이 묶여 있어서
독립 단위가 24개뿐이고, 그중 '절점삭제' 27쌍은 14묶음(6·4·3쌍짜리 묶음 포함)이다.
테스트 숫자가 CV 보다 낮은 건 모델 계열과 무관했다 — 같은 테스트에서 gbm(oneshot)도
34.9% → 25.0%, refit GNN 도 39.7% → 26.9% 로 비슷하게 떨어졌고, '연결만 변경' 은 세
모델 모두 CV 와 같았다(60%). 떨어진 곳은 '절점삭제' 하나이고, 거기서는 **사람의 수정조차
심판이 정상으로 보는 비율이 59%**(CV 84%)라 평소와 다른 결함이 몰린 표본으로 보인다.
실패 양상은 '아예 안 합침' 이 절반(13/27, CV 27%)이다.

테스트 셋을 연 기록 (숨기지 않는다):
1. 테스트를 보기 전에 정한 규칙(CV 최고)으로 고른 `regen_gnn_list_gbm2`(refit) → **26.9%**
   (14/52). 함께 정해 둔 기준선 `regen_gbm_oneshot` → 25.0%.
2. 그 결과를 보고 refit 의 눈금 문제를 의심했고, **학습 셋 안 중첩 CV 로만** 확인해 배포
   방식을 fold 평균으로 바꿨다(6.4). 거기에 씨앗 평균과 누적 면적 가드(버그 수정)를 더한
   `regen_final` → 25.0%. 이 숫자는 테스트를 한 번 본 뒤의 것이다.

**할 줄 아는 것 / 못 하는 것.** 삼각형 쌍을 사각형으로 합치는 수정('연결만 변경')은 CV·
테스트 모두 60% 를 정확히 맞힌다. 절점을 합치는 수정은 어디를 합칠지는 대체로 짚지만
(지운 요소 정밀 0.72) 멈춤 판단이 보수적이라 **덜 고치는** 쪽으로 틀린다. 정확히 같지
않아도 결과 메쉬의 품질(불량각·삼각형 수)은 사람 결과에 가깝다. 절점 추가·좌표 이동·
연산 밖 재배치(전체의 24%)는 이 연산 체계로는 원래 못 한다.

### 6.6 화면 — 무엇을 지우고·만들고·옮겼나

```bash
streamlit run GNN_GAE/src/app_regen.py
```

2×2 로 **원본 → 모델 재생성**(위)과 **원본 → 사람 수정**(아래)을 놓고 네 화면의 시점을
연동한다.

| 강조 | 뜻 |
|---|---|
| 빨강 면·테두리 (왼쪽) | 지운 요소 |
| 초록 면·테두리 (오른쪽) | 새로 만든 요소 |
| 자주 X (왼쪽) | 사라진 절점 자리 |
| 노랑 마름모 + 점선 화살표 | 자리를 옮긴 절점 (흰 점 = 출발, 마름모 = 도착) |
| 굵은 빨강/초록 선 | 지운 1D / 새로 생긴 1D |
| 주황 굵은 테두리 | **상대 쪽에는 없는 변경** (위 = 모델만 한 것, 아래 = 모델이 놓친 것) |

강조는 도구막대에서 하나씩 끄고 켠다(끄면 회색으로 돌아간다). "변경 위치로 확대…" 에서
변경 하나를 고르면 네 화면이 그 자리로 확대된다. 아래 표에 같은 변경 목록(누가 / 무엇을 /
상대 쪽도 했나)이 있고, 재생성 .bdf/.json 을 내려받을 수 있다.

화면은 모델을 돌리지 않는다. 채점 때 기록한 연산을 원본에 다시 적용해 그린다 — 그래서
채점된 결과와 정확히 같고(재적용 = 결과 100% 확인) torch 없이도 열린다. 테스트 셋은
`eval_test.csv`, 학습 셋은 out-of-fold 결과(`eval_cv.csv`)를 보여준다.

```bash
python src/regen_eval.py --run runs/regen_final --split cv     # 학습 셋 out-of-fold 채점
```

뷰어는 좌우 **시점이 연동**된다. 색: 빨강 = 없어진 요소, 초록 = 새로 생긴 요소,
자주색 X = 사라지거나 새로 생긴 절점, 노란 마름모 = 자리를 옮긴 절점,
검은 테두리 = 불량각 요소, 파랑/주황 = 1D 요소 / 같이 지워야 하는 1D 요소.

## 9. 알아둘 점 — 실제로 물린 것들

전부 회귀 테스트(`check_edits.py`)나 주석에 박아뒀다.

### 절점 대응 판정

- **좌표로 병합을 판정하면 안 된다.** 사람은 합친 뒤 자리를 다시 잡기도 하고(`_1081`,
  흡수한 절점 자리에서 45mm 떨어짐), 셋을 한 점으로 모으기도 한다(`_0021`).
  좌표 기준으로는 451건 중 99건밖에 못 잡았다.
- **1:N 병합이 있다.** 한 절점이 2개를 흡수한 경우 22건, 3개 1건. 1:1 로 가정하면
  `_0021` 처럼 비교 대상을 잘못 골라 오판한다.
- **사라진 쉘과 새 쉘이 우연히 한 자리만 다를 수 있다.** 그때 엉뚱한 절점이 흡수자로
  뽑힌다(`_0032`). 인접성과 좌표 증거를 함께 봐야 한다.
- **퇴화로 사라진 쉘에서도 배울 게 있다.** 두 절점이 합쳐지면 삼각형이 찌그러져
  없어지므로 "바뀐 쉘" 이 안 생긴다. 그 경로를 안 보면 `_0021` 의 23439 를 놓친다.

### 편집 연산

- **1D 요소가 올라탄 변도 없앨 수 있다.** 금지가 아니다 — 사람은 손댄 구역 1D 의
  19%(361/1886)를 지웠다. `drop_lines=True` 로 함께 지운다. 기본값은 거부(보강재를
  지우는 건 결과가 큰 결정이라 부르는 쪽이 명시적으로 골라야 한다).
- **오목(reflex) 사각형은 품질 지표로 안 걸린다.** `features.interior_angles` 가 acos
  기반이라 182° 를 178° 로 보고하고, 내각 합도 355.8°로 360°에 가깝다.
- **이면각만 보는 가드는 뚫린다.** 이면각 0.14°인데 다른 대각선으로 보면 90° 접힌
  4점이 있다. **면적 보존을 직접 검사**하면 이것·오목·다른 패널을 한 번에 막는다.
- **split 도 비매니폴드를 늘릴 수 있다** — 새 대각선이 이미 있는 변이면.
- **면적 보존은 연산 단위로** 본다. 단일 연산은 최대 3.7e-5, 무작위 왕복 수열은
  원본 대비 1.7e-3 까지 드리프트한다.
- **법선 뒤집힘은 요소 id + 절점 집합으로** 대응시킨다. 이 데이터셋은 쉘 감김 방향이
  제멋대로다.
- **좌표를 `%.6g` 로 쓰면 안 된다** — 24만 단위라 유효숫자가 모자라 0.5mm 가 잘린다.

### 뷰어

- **plotly 3D 는 `plotly_relayout` 이 드래그마다 뜨지 않는다** (6.5 실측). 이벤트 대신
  두 씬의 카메라를 매 프레임 비교해 민다.
- **창이 가려지면 `requestAnimationFrame` 이 멈춘다.** `setInterval` 로 받친다.
- **복사가 끝난 뒤 '현재' 카메라를 기준값으로 삼으면 안 된다** — relayout 중에 더 끈
  만큼이 흡수돼 반대쪽이 영구히 뒤처진다. **보낸 카메라 그 자체**를 기준으로 둔다.
- **사라진 절점과 옮겨간 절점을 같은 색으로 찍으면 안 된다.** 흡수한 쪽이 흡수된 쪽
  자리로 정확히 가는 일이 흔해서(99건), 좌우 화면 같은 지점에 마커가 찍힌 것처럼
  보인다(`_0014`). 출발 위치도 함께 찍어야 "어디서 어디로" 가 보인다.
- **`st.cache_data` 는 데코레이터가 붙은 함수의 코드만 해시한다.** 다른 모듈만 고치면
  캐시가 안 비워진다 — 그 파일 수정시각을 캐시 키에 끼운다.
- **Streamlit 표 폭 인자가 1.49 에서 바뀌었다** (`use_container_width` → `width`).
- **같은 자리에 면을 두 장 겹치면 깜빡인다** (z-fighting). 강조를 끄고 켤 때 색을 바꾸지
  말고 '색칠한 것 / 회색 사본' 두 트레이스 중 하나만 보이게 한다.
- **'변경 위치로' 확대 반경을 변 길이 4배로 잡으면 오히려 축소된다** — 패치가 작아서
  메쉬 전체보다 넓다. 중앙 변 길이의 1.2배로 둔다.

### 재생성

- **사람은 남길 절점 번호를 일정하게 고르지 않는다.** 흡수한 번호를 흡수된 자리로 옮기기도
  하고(99건) 제 번호를 제자리에 두기도 한다(343건). 그래서 결과 비교는 **좌표**로 한다
  (`meshdiff.signature`). 재생성은 "자리가 남는 절점의 번호가 남는다" 로 고정해 좌표를
  하나도 옮기지 않는다.
- **셋이 하나로 모일 때 방향은 그룹 단위로 정한다** (`_0021`). 쌍마다 정하면 최종 자리가
  남은 번호의 자리가 아니라서 틀린다.
- **절점 병합은 묶음으로 검사해야 한다** (`_0274`). 하나씩 하면 중간 상태에서 사각형이
  오목해지거나 세 점이 일직선이 되는데, 둘 다 하면 깨끗한 삼각형이 된다.
- **사람도 ext 절점을 합치고 면적을 바꾼다** — ext 자리 60개(48쌍), 총 면적 0.1% 넘게
  바뀐 쌍 107개(최대 2.6%). 그래서 `check(regen=True)` 에서는 경고로 돌린다. ext 이동은
  여전히 위반.
- **면적 가드는 원본 대비 누적으로 본다.** 병합 하나하나는 5% 안이어도 4번 쌓여 +6.3%가
  된 메쉬가 있었다(`_0231`). 학습이 덜 된 모델이 병합 35개를 골라 면적 36%를 날린 적도
  있어서 메쉬당 병합 상한(10개)도 둔다.
- **겹치는 패치 때문에 무작위 분할은 새어 나간다.** 같은 결함이 최대 10개 패치에 있다.
  묶음 단위로 나눠야 한다 (6.2).
- **CV 로 고른 임계값은 다시 학습한 모델에 그대로 안 맞는다.** 점수 눈금이 달라진다.
  fold 모델들의 평균을 배포한다 (6.4).
- **임계값 격자 끝에 최적이 걸리면 격자를 넓힌다.** 2단계 최적이 처음 격자의 하한(0.2)에
  계속 걸렸다.
- **1단계 후보 캐시는 '결과에 영향을 주는 함수의 소스' 로 버전을 매긴다.** 파일 통째로
  해시하면 무관한 수정에도 메쉬당 0.5초 × 1000여 개를 다시 계산한다. 여러 학습을 동시에
  돌리므로 캐시는 임시 파일에 쓰고 바꿔 끼운다.
