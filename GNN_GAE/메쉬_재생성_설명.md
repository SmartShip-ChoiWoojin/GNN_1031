# 메쉬 재생성 — 무엇을, 왜, 어떻게 했나

이 문서는 GNN_GAE 폴더의 **메쉬 재생성** 작업을 처음 보는 사람이 읽고 이해할 수 있도록
쓴 설명서입니다. 코드를 열어 보지 않아도 전체 흐름과 결과를 설명할 수 있게 하는 것이
목표입니다. 더 자세한 기술 기록은 [README.md](README.md) 6절과 9절에 있습니다.

읽고 나면 다음을 설명할 수 있습니다.

1. 어떤 문제를 풀었는가
2. 왜 "메쉬를 새로 그리는" 대신 "편집 연산을 고르는" 방식을 택했는가
3. 데이터를 어떻게 나눴고, 그 과정에서 무엇을 조심했는가
4. 모델이 실제로 무엇을 계산하는가
5. 결과가 어떤가, 무엇을 잘하고 무엇을 못하는가
6. 화면에서 무엇을 볼 수 있는가

---

## 0. 먼저 알아 둘 용어

| 용어 | 뜻 |
|---|---|
| 메쉬 패치 | 선체 FE 모델에서 잘라 낸 작은 조각 하나. 파일 하나(.bdf + .json)가 패치 하나입니다. 절점 약 55개, 요소 약 50개 크기입니다. |
| 절점 (GRID) | 메쉬의 꼭짓점. 번호와 x, y, z 좌표를 가집니다. |
| 쉘 요소 | 면 요소. 사각형(CQUAD4)과 삼각형(CTRIA3) 두 종류가 있습니다. |
| 1D 요소 | 선 요소(CBAR, CBEAM). 보강재이며 항상 쉘 요소의 변 위에 놓여 있습니다. |
| ext 절점 | 이웃 패치와 공유하는 절점(.json 에 표시). 패치를 잘라 낸 경계에 있습니다. |
| Bad / Good | Bad = 비정상으로 판정된 원본 메쉬, Good = 그것을 사람이 직접 고친 메쉬. |
| 쌍 | Bad 하나와 그것을 고친 Good 하나. 이번 데이터는 508쌍입니다. |
| 절점 병합 | 절점 하나를 이웃 절점에 합쳐 없애는 편집. 이 작업의 1단계 연산입니다. |
| 삼각형 쌍 병합 | 변을 공유하는 삼각형 2개를 사각형 1개로 합치는 편집. 2단계 연산입니다. |
| 후보 | 모델이 고를 수 있는 편집 하나하나. 예: "절점 A 를 절점 B 에 합친다". |
| 학습 셋 / 테스트 셋 | 모델을 만드는 데 쓰는 데이터(90%) / 마지막 채점에만 쓰는 데이터(10%). |
| CV, fold | 교차검증. 학습 셋을 5조각(fold)으로 나눠, 한 조각씩 빼고 나머지로 학습한 뒤 뺀 조각을 채점합니다. |
| out-of-fold | CV 에서 각 메쉬를 "그 메쉬를 학습에 쓰지 않은 모델"로 채점한 결과. |
| 임계값 | 점수가 이 값을 넘을 때만 편집을 실행하는 기준값. |
| 정확 일치 | 모델이 만든 메쉬가 사람이 고친 메쉬와 요소·1D·좌표까지 완전히 같은 경우. 이 작업의 주 지표입니다. |
| 심판 분류기 | 상위 프로젝트에서 만든 "정상/비정상" 판정 모델(`deploy_10_14`). 이 508쌍의 원본은 그 모델의 학습에 쓰지 않았습니다. 보조 채점용으로 씁니다. |

## 1. 풀려는 문제

- **입력**: 비정상으로 판정된 메쉬 패치(Bad)
- **출력**: 사람이 고쳤을 법한 메쉬(Good 과 같은 형태의 .bdf/.json)
- **데이터**: 현업에서 사람이 직접 고친 Bad/Good 508쌍
- **요구 사항**
  - 데이터의 10%는 테스트용으로 남기고 90%로 학습한다
  - 화면에서 무엇을 지웠는지, 무엇을 만들었는지, 무엇을 옮겼는지 강조해서 보여준다
  - 검증까지 한다

## 2. 핵심 아이디어 — 메쉬를 새로 그리지 않고, 편집을 고른다

### 2.1 새로 그리지 않은 이유

메쉬를 처음부터 새로 만들어 내는 모델(그래프 생성 모델)도 생각할 수 있지만 쓰지 않았습니다.
이유는 세 가지입니다.

1. **유효한 .bdf 를 보장하기 어렵습니다.** 1D 요소는 반드시 쉘 변 위에 있어야 하고, ext
   절점은 움직이면 안 되고, 요소가 서로 겹치면 안 됩니다. 생성 모델은 이런 조건을 매번
   지킨다는 보장이 없습니다.
2. **사람의 수정은 작고 국소적입니다.** 508쌍을 분석해 보니 74.8%가 한 군데에서만
   바뀌었습니다. 50개 요소 중 대부분은 그대로 둡니다.
3. **사람이 쓴 편집 동작이 몇 가지로 정리됩니다.** (다음 절)

그래서 **"원본에 어떤 편집을 순서대로 적용할지 고르는"** 방식으로 정했습니다. 편집 연산
하나하나는 미리 만들어 두고 검사까지 붙여 두었기 때문에, 모델이 무엇을 고르든 결과
메쉬는 항상 유효합니다.

### 2.2 사람은 실제로 무엇을 했나

508쌍에서 사람이 한 일을 분해하면 거의 전부가 두 가지 편집입니다.

| 편집 | 사람 수정에서의 비중 |
|---|---|
| **절점 병합** — 절점 하나를 이웃 절점에 합친다 | 사라진 절점 481개 중 451개가 이것 |
| **삼각형 쌍 병합** — 삼각형 2개를 사각형 1개로 합친다 | '연결만 변경' 종류(196쌍)의 97% |

그래서 재생성은 두 단계로 합니다.

```
원본(Bad) ──[1단계: 절점 병합]──▶ 중간 메쉬 ──[2단계: 삼각형 쌍 병합]──▶ 재생성 결과
```

### 2.3 이 두 편집만으로 사람 결과를 얼마나 똑같이 만들 수 있나

모델을 만들기 전에 먼저 확인했습니다. 사람이 한 수정을 위의 두 편집의 순서로 바꿔 적고,
그것을 실제 편집 코드로 다시 실행해서 사람 결과와 비교했습니다 (`regen_oracle.py`).

**508쌍 중 388쌍(76.4%)이 요소·1D·좌표까지 정확히 같게 재현됩니다.**

이 숫자가 이 방식으로 도달할 수 있는 **최대치(상한)** 입니다. 모델이 완벽해도 76.4%를
넘을 수 없습니다. 나머지 120쌍은 두 편집으로 설명되지 않는 수정이 섞여 있습니다.

| 재현되지 않는 이유 | 쌍 수 |
|---|---:|
| 두 편집 밖의 재배치 (삼각형+사각형을 다르게 다시 나누기, 사각형 쪼개기 등) | 40 |
| 절점을 새로 추가함 | 25 |
| 요소는 맞는데 1D 요소가 다름 | 18 |
| 이어받는 절점 없이 절점을 지움 | 13 |
| 절점 좌표를 옮김 | 11 |
| 편집 검사에서 거부됨 (멀리 떨어진 절점끼리 합친 경우 등) | 8 |
| 지운 절점 자리를 새 절점으로 바꿈 | 5 |

## 3. 두 편집 연산 자세히

두 연산은 모두 `meshedit.py` 에 있습니다. 모델은 "어느 연산을 어디에 적용할지" 만 정하고,
실제 메쉬 수정은 항상 이 코드가 합니다.

### 3.1 절점 병합 (1단계)

"절점 r 을 절점 k 에 합친다" 는 다음 뜻입니다.

- 절점 r 이 메쉬에서 없어지고, r 을 쓰던 요소는 대신 k 를 씁니다.
- **k 는 제자리에 있습니다.** 좌표는 하나도 바뀌지 않습니다.
- r 과 k 는 변으로 이어져 있거나, 같은 사각형의 마주 보는 꼭짓점이어야 합니다.
  (사람이 합친 451쌍 중 98.4%가 이 경우입니다.)

r 을 쓰던 요소는 이렇게 바뀝니다.

| r 을 쓰던 요소 | 결과 |
|---|---|
| r 과 k 를 둘 다 가진 삼각형 | 꼭짓점이 2개만 남으므로 **사라짐** |
| r 과 k 가 변으로 이어진 사각형 | 꼭짓점 3개가 남아 **삼각형이 됨** |
| r 과 k 가 마주 보는 사각형 | 면적이 0 이 되므로 **사라짐** |
| k 는 없고 r 만 가진 요소 | 꼭짓점 r 이 k 로 바뀌어 **모양이 바뀜** |
| 1D 요소 | 끝점 r 이 k 로 바뀜. 길이가 0 이 되면 사라짐 |

**방향이 중요합니다.** "A 를 B 에 합침" 과 "B 를 A 에 합침" 은 남는 자리가 달라서 결과
모양이 다릅니다. 그래서 두 방향을 서로 다른 후보로 취급합니다.

다음 경우에는 연산을 **거부**하고 메쉬를 그대로 둡니다.

- 남는 요소가 뒤집히거나(법선 방향 반전) 면적이 0 에 가까워지는 경우
- 남는 사각형이 오목해지는 경우
- 세 개 이상의 요소가 공유하는 변(비매니폴드 변)이 늘어나는 경우
- 1D 요소가 쉘 변 위를 벗어나는 경우
- 메쉬 전체 면적이 5% 넘게 바뀌는 경우

**여러 병합은 한꺼번에 적용하고 마지막 상태만 검사합니다.** 하나씩 검사하면 중간 상태에서만
문제가 생기는 경우가 있기 때문입니다. 예를 들어 `_0274` 에서는 병합 하나만 하면 사각형
하나가 내각 177° 로 오목해지지만, 두 병합을 다 하면 그 사각형은 깨끗한 삼각형이 됩니다.

ext 절점을 합치는 것은 막지 않았습니다. 사람도 508쌍 중 48쌍에서 ext 절점 60개를 이웃
ext 절점에 합쳤기 때문입니다. 대신 화면과 검사 결과에 **경고**로 표시합니다. ext 절점을
**움직이는** 것은 여전히 금지입니다.

### 3.2 삼각형 쌍 병합 (2단계)

변을 공유하는 삼각형 2개를 사각형 1개로 합칩니다. 공유하던 변이 사라집니다.

```
 a ───── b          a ───── b
 │     ╱ │          │       │
 │   ╱   │    →     │       │
 │ ╱     │          │       │
 d ───── c          d ───── c
 삼각형 2개          사각형 1개
```

다음 경우에는 거부합니다.

- 두 삼각형이 서로 다른 면에 있어 많이 꺾여 있는 경우 (사이각 20° 초과)
- 합친 사각형이 오목해지는 경우
- 합치기 전후로 면적이 1% 넘게 바뀌는 경우

공유하던 변 위에 1D 요소가 있으면 그 1D 요소도 함께 지웁니다. 사람도 손댄 구역 안 1D
요소의 19%를 지웠습니다.

## 4. 결과를 어떻게 비교하나 — 절점 번호가 아니라 좌표로

모델 결과와 사람 결과가 같은지 볼 때 **절점 번호는 보지 않고 좌표로 비교**합니다
(`meshdiff.py`).

이유: 사람은 두 절점을 합칠 때 남길 번호를 일정하게 고르지 않았습니다.

- 99건: 흡수한 절점의 번호를 남기고, 그 절점을 흡수된 절점의 자리로 옮김
- 343건: 흡수한 절점의 번호를 남기고, 제자리에 둠

앞의 경우와 "흡수된 절점의 번호와 자리를 그대로 남긴" 경우는 결과 메쉬의 모양이
완전히 같습니다. 번호만 다릅니다. 번호로 비교하면 같은 결과를 다르다고 판정하게 됩니다.

그래서 각 요소를 "꼭짓점 좌표의 집합" 으로 표현해서 비교합니다.

- **정확 일치**: 쉘 요소, 1D 요소, 절점 좌표가 모두 사람 결과와 같음
- **부분 점수**: 사람이 지운 요소를 모델도 지웠는지(정밀도·재현율), 사람이 만든 요소를
  모델도 만들었는지, 바뀐 요소 전체가 얼마나 겹치는지(IoU)

재생성 모델은 "자리가 남는 절점의 번호가 남는다" 로 고정했기 때문에 좌표를 옮기지
않습니다. 그래서 화면에서 "옮긴 절점" 은 사람 결과에만 나타날 수 있습니다.

## 5. 데이터 나누기 — 학습 90%, 테스트 10%

### 5.1 고정된 분할 파일

`runs/regen_split.csv` 에 한 번 만들어 두고 다시 계산하지 않습니다 (`regen_data.py`).
학습 456쌍, 테스트 52쌍입니다. 테스트 셋은 학습, 임계값 조정, 모델 선택 어디에도 쓰지 않고
마지막 채점에만 씁니다. 수정 종류('절점삭제', '연결만 변경', 기타)의 비율이 양쪽에 비슷하게
들어가도록 나눴습니다.

### 5.2 같은 결함은 한쪽에만 두었습니다

처음에는 무작위로 나눴는데, 확인해 보니 문제가 있었습니다.

- 패치들이 서로 겹쳐서, **같은 결함이 여러 패치에 들어 있습니다** (한 결함이 최대 10개 패치).
- 508쌍 중 334쌍이 "사람이 지운 요소" 를 다른 쌍과 공유합니다.
- 무작위 분할에서는 **테스트 51쌍 중 32쌍이 학습 셋에 같은 결함을 고친 쌍을 두고**
  있었습니다. 이러면 모델이 같은 결함을 학습에서 미리 보게 되어 테스트 점수가 실제보다
  높게 나옵니다.

그래서 다음 두 조건 중 하나라도 맞는 쌍들을 한 묶음으로 보고, **묶음 단위로** 나눴습니다.

- 사람이 지운 요소를 하나라도 공유한다
- 원본 요소가 50% 넘게 겹친다

결과는 259묶음(가장 큰 묶음 10쌍)이고, 학습 셋과 테스트 셋이 공유하는 묶음은 0개입니다.
학습 셋 안에서 CV 를 할 때도 같은 묶음 단위로 5조각을 나눠 파일에 적어 두었습니다.

이 문제는 테스트 셋으로 한 번도 채점하기 전에 발견해서 분할을 다시 만들었습니다.
그 전에 학습한 결과는 `runs/_archive_leaky_split/` 에 따로 두었고 비교에 쓰지 않습니다.

## 6. 모델이 하는 일

### 6.1 전체 흐름

```
원본 메쉬
   │
   ├─ 1단계 반복:
   │    ① 지금 메쉬에서 가능한 절점 병합 후보를 모두 만든다 (메쉬당 약 200개)
   │    ② 각 후보의 점수와 '멈춤' 점수를 계산한다
   │    ③ 최고 후보 점수 - 멈춤 점수 가 임계값보다 크면 그 병합을 적용하고 ①로 돌아간다
   │       아니면 1단계를 끝낸다
   ▼
중간 메쉬
   │
   ├─ 2단계 한 번:
   │    ① 변을 공유하는 삼각형 쌍 후보를 모두 만든다 (메쉬당 약 2개)
   │    ② 각 후보의 확률을 계산한다
   │    ③ 임계값을 넘는 후보를 점수 순으로, 같은 삼각형을 두 번 쓰지 않게 적용한다
   ▼
재생성 결과 (.bdf / .json)
```

### 6.2 후보 만들기

- 1단계 후보: 변으로 이어진 절점 쌍과 사각형의 마주 보는 꼭짓점 쌍. 방향을 나눠 양쪽 모두.
- 2단계 후보: 변을 공유하는 삼각형 쌍.
- 각 후보를 메쉬 사본에 **실제로 적용해 보고**, 3절의 검사에서 거부되면 후보에서 뺍니다.
  그래서 모델이 무엇을 고르든 항상 적용할 수 있습니다.
- 사람이 한 절점 병합의 95.6%, 삼각형 쌍 병합의 100%가 후보 목록 안에 들어 있습니다.

### 6.3 후보를 설명하는 값 (피처) — 미리 적용해 보고 잽니다

각 후보에 대해 숫자 52개를 계산합니다 (`regen_feats.py`). 대표적인 것은 다음과 같습니다.

- **적용 전 주변 상태**: 두 절점 주변 요소의 최소 내각, 최대 내각, skew, aspect,
  불량 요소(내각 30° 미만 또는 150° 초과) 수, 삼각형 수
- **적용 후 주변 상태**: 같은 값을 병합한 뒤에 다시 잰 것
- **변화량**: 불량 요소가 몇 개 줄었나, 최소 내각이 얼마나 커졌나, 면적이 얼마나 바뀌었나
- **두 절점의 성질**: ext 여부, 붙은 요소 수, 붙은 1D 요소 수, 경계에 있는지
- **변의 길이**: 메쉬의 중앙 변 길이 대비 비율

"적용 후" 값을 넣은 이유는, 사람이 수정할 곳을 고를 때 보는 것이 결국 "고친 뒤에 주변이
좋아지는가" 이기 때문입니다.

### 6.4 1단계: 그래프 신경망(GNN)이 후보와 '멈춤' 중에서 고릅니다

**입력 그래프**: 상위 프로젝트의 요소기반 그래프를 그대로 씁니다. 노드 하나가 요소 하나이고,
요소끼리 변이나 꼭짓점을 공유하면 엣지로 이어집니다.

**출발점**: 심판 분류기의 그래프 인코더(요소마다 128차원 벡터를 만드는 부분)를 가져와서
시작합니다. 그 모델은 메쉬 2,549개로 "어느 요소가 비정상적인가" 를 이미 학습했고, 학습
데이터가 456쌍뿐인 이번 작업에서는 처음부터 학습하는 것보다 유리합니다. (이 508쌍의
원본은 그 모델의 학습에 쓰지 않았습니다.)

**후보 점수 계산**

1. 인코더가 요소마다 벡터를 만듭니다.
2. 절점마다, 그 절점에 붙은 요소 벡터들의 평균과 최댓값을 이어 붙여 절점 벡터를 만듭니다.
3. 후보 "r 을 k 에 합침" 의 점수 = [r 의 절점 벡터, k 의 절점 벡터, 후보 피처 52개] 를
   작은 신경망에 넣은 결과. r 과 k 의 자리가 정해져 있어서 방향에 따라 점수가 다릅니다.

**'멈춤' 점수**: 메쉬 전체의 요소 벡터 평균·최댓값과 메쉬 상태(요소 수, 삼각형 수, 불량
요소 수 등)로 "더 고칠 곳이 없다" 의 점수를 따로 계산합니다.

**학습 방법**: 메쉬마다 [모든 후보 점수, 멈춤 점수] 를 한 줄로 놓고, 정답(사람이 한 병합)이
가장 높은 점수를 받도록 학습합니다. 남은 정답이 없으면 '멈춤' 이 가장 높도록 학습합니다.

**학습 데이터에 중간 상태를 넣었습니다**: 원본 456개만이 아니라, 사람이 한 병합을 일부만
적용한 중간 메쉬 462개를 함께 씁니다 (총 918개). 중간 메쉬에서는 아직 안 한 병합이
정답이고, 전부 적용한 메쉬에서는 '멈춤' 이 정답입니다. 이렇게 해야 두 번째, 세 번째 병합과
"언제 멈출지" 를 배울 수 있습니다.

**왜 하나씩 반복하는 방식인가**: 처음에는 원본에서 모든 후보에 한 번에 점수를 매기고
임계값을 넘는 것을 모두 적용했습니다. 그런데 결과를 나눠 보니 두 가지가 약했습니다.

- 병합이 2개 이상 필요한 메쉬에서 개수를 못 채웠습니다. 첫 병합을 하면 두 번째 자리의
  모양이 바뀌는데, 한 번에 점수를 매기면 그 변화를 볼 수 없습니다.
- "이 메쉬에 병합이 필요한가" 를 임계값 하나로 가르기 어려웠습니다.

반복 방식으로 바꾸고 나서 병합 개수별 정확 일치는 이렇게 바뀌었습니다 (학습 셋 CV, 두 편집으로
재현 가능한 349쌍 기준).

| 사람이 한 병합 수 | 한 번에 고르기 | 하나씩 반복 + 멈춤 |
|---|---:|---:|
| 0개 | 64.9% | 60.1% |
| 1개 | 47.3% | 51.8% |
| 2개 | 16.7% | 25.0% |
| 3개 이상 | 4.8% | 23.8% |

### 6.5 2단계: 삼각형 쌍 고르기

2단계는 gradient boosting(HistGradientBoosting) 모델이 후보 피처만 보고 확률을 냅니다.
GNN 도 시도했지만, 2단계 후보가 학습 셋 전체에 약 950개뿐이라 gradient boosting 이 더
나았습니다. 1단계가 정확히 맞았을 때 2단계까지 완성하는 비율이, 합칠 쌍이 1개인 메쉬에서
85%(gradient boosting) 대 79%(GNN) 였습니다.

### 6.6 안전장치

- 메쉬 하나에서 절점 병합은 최대 10개까지만 합니다. (사람은 최대 7개였습니다.)
- 병합을 여러 번 하면서 쌓인 면적 변화가 원본 대비 5%를 넘으면 그 병합은 하지 않고 다음
  후보로 넘어갑니다. (병합 4번에 +6.3%가 된 메쉬가 실제로 있었습니다.)
- 마지막에 모든 결과를 `meshedit.check()` 로 다시 검사합니다.

## 7. 학습과 임계값 정하기

### 7.1 무엇을 정해야 하나

임계값이 두 개 있습니다.

- 1단계: "최고 후보 점수 - 멈춤 점수" 가 이 값보다 커야 병합합니다. (최종값 0.50)
- 2단계: 확률이 이 값보다 커야 삼각형 쌍을 합칩니다. (최종값 0.05)

실제로 쓸 때는 몇 군데를 고쳐야 하는지 알 수 없으므로, 이 개수까지 모델이 정해야 합니다.

### 7.2 학습 셋 안에서만 정합니다

`regen_train.py` 의 순서는 다음과 같습니다.

1. 학습 셋 456쌍을 묶음 단위 5조각으로 나눕니다.
2. 조각 하나를 빼고 나머지 4조각으로 학습한 뒤, 뺀 조각의 메쉬를 재생성합니다.
   이것을 5번 하면 456쌍 모두가 "자기를 학습에 안 쓴 모델" 로 한 번씩 재생성됩니다.
3. 여러 임계값 조합으로 재생성해 보고, 사람 결과와 정확히 일치하는 비율이 가장 높은
   조합을 고릅니다.

테스트 셋은 이 과정에서 전혀 쓰지 않습니다.

### 7.3 여러 설정 비교

같은 조각 나눔으로 7가지 설정을 비교했습니다 (학습 셋 CV, 456쌍).

| 설정 | 정확 일치 | 재현 가능한 쌍 중 | 바뀐 요소 IoU |
|---|---:|---:|---:|
| gradient boosting, 한 번에 고르기 | 34.9% | 45.0% | 0.531 |
| gradient boosting, 하나씩 반복 | 38.4% | 49.3% | 0.590 |
| GNN, 한 번에 고르기 | 38.6% | 49.0% | 0.567 |
| GNN, 하나씩 반복 (멈춤 없이) | 36.0% | 46.1% | 0.531 |
| GNN, 하나씩 반복 + 멈춤 | 39.0% | 50.4% | 0.583 |
| GNN, 하나씩 반복 + 멈춤 + 추가 피처 | 38.8% | 49.6% | 0.578 |
| **GNN 반복 + 멈춤, 2단계는 gradient boosting** | **39.7%** | **51.0%** | 0.586 |

맨 아래 설정을 최종 설정으로 정했습니다. 다만 위쪽 설정들 사이의 차이(38~40%)는 크지
않습니다. 같은 설정을 두 번 학습해도 GPU 계산의 미세한 차이 때문에 결과가 2%p 정도
달라졌습니다. 그래서 이 표에서 "어느 하나가 확실히 낫다" 고 말할 수는 없고, "하나씩 반복하는
방식이 한 번에 고르는 방식보다 낫다" 정도가 확실한 결론입니다.

### 7.4 배포 모델은 다시 학습하지 않고, CV 모델들의 평균을 씁니다

처음에는 CV 로 임계값을 정한 뒤, 학습 셋 전부로 모델을 **다시 학습**해서 배포했습니다.
그런데 테스트에서 절점을 합쳐야 하는 메쉬 31개 중 15개에서 아무것도 합치지 않았습니다.
다시 학습한 모델은 점수의 크기가 CV 때의 모델과 달라서, CV 로 정한 임계값이 맞지 않을 수
있습니다.

이 추측을 테스트 셋을 다시 쓰지 않고 확인하기 위해, 학습 셋 안에서만 같은 상황을 재현해
봤습니다 (`regen_nested.py`). CV 조각 하나를 테스트처럼 떼어 두고, 나머지로 임계값을 정한 뒤
"다시 학습한 모델" 과 "CV 모델 4개의 평균" 을 떼어 둔 조각에서 비교했습니다. 이것을 5조각
모두 반복했습니다.

| 배포 방식 | 정확 일치 (456쌍) | 메쉬당 병합 수 (정답 0.875) | 조각별 병합 수 |
|---|---:|---:|---|
| CV 모델들의 평균 | **39.5%** | 0.55 | 0.68 / 0.55 / 0.57 / 0.47 / 0.48 |
| 다시 학습 | 37.3% | 0.76 | 1.24 / 0.66 / 0.65 / 0.88 / 0.36 |

다시 학습한 모델은 조각마다 병합 수가 크게 달라집니다. 어떤 경우에는 너무 많이 합치고
어떤 경우에는 너무 적게 합칩니다. 평균 모델은 조금 덜 합치는 경향이 있지만 일정합니다.
그래서 **최종 모델은 CV 에서 만든 모델들의 평균**으로 정했습니다. 여기에 학습 시작값(씨앗)을
3가지로 바꿔 학습해서, 5조각 × 3씨앗 = **모델 15개의 평균**을 씁니다
(`runs/regen_final`).

### 8.2 CV 숫자와 테스트 숫자 중 무엇을 믿어야 하나

**CV 숫자(39.7%)가 더 믿을 만합니다.** 이유는 다음과 같습니다.

- 테스트에서 점수가 떨어진 것은 모델 종류와 관계없었습니다. 피처만 쓰는 gradient boosting

  59% 입니다 (CV 에서는 84%). 평소와 다른, 더 어려운 결함이 몰려 있는 것으로 보입니다.

1. 테스트를 보기 전에 "CV 정확 일치가 가장 높은 설정" 으로 고른 모델(다시 학습한 버전)을
   채점했습니다 → **26.9%** (14/52). 함께 정해 둔 기준 모델(gradient boosting, 한 번에
   고르기)은 25.0% 였습니다.
2. 그 결과를 보고 7.4절의 문제를 의심했고, **학습 셋 안에서만** 확인한 뒤 배포 방식을
   평균 모델로 바꿨습니다. 면적 누적 검사(6.6절)도 이때 고쳤습니다.
3. 최종 모델을 채점했습니다 → **25.0%** (13/52). 이 숫자는 테스트 셋을 한 번 본 뒤의

### 8.4 잘하는 것과 못하는 것

**잘하는 것**

- 삼각형 쌍을 사각형으로 합치는 수정('연결만 변경')은 CV·테스트 모두 60%를 정확히 맞힙니다.
- 사람과 완전히 같지 않더라도, 결과 메쉬의 품질(불량각 요소 수, 삼각형 수)은 사람 결과와
  비슷한 수준까지 좋아집니다.
- 어떤 결과도 메쉬 검사를 위반하지 않습니다.

**못하는 것**

- 절점을 합치는 수정이 약합니다. 고칠 위치는 대체로 맞게 짚지만(모델이 지운 요소의 72%를
  사람도 지움), "멈춤" 판단이 보수적이라 **덜 고치는** 쪽으로 틀립니다. 테스트의 '절점삭제'
  27쌍 중 13쌍에서 아무것도 합치지 않았습니다.
- 절점 추가, 좌표 이동, 두 편집 밖의 재배치는 이 방식으로는 원래 할 수 없습니다
  (전체의 약 24%).

## 9. 화면 보는 법

```bash
streamlit run GNN_GAE/src/app_regen.py
```

### 9.1 화면 배치

3D 화면 3개가 놓이고, **세 화면의 시점이 연동**됩니다. 하나를 돌리면 나머지도 같이 돌아갑니다.

```
┌──────────────────────┬────────────────────────┐
│                      │ 모델 재생성 결과         │
│  원본 (비정상 메쉬)    ├────────────────────────┤
│                      │ 사람 수정 결과           │
└──────────────────────┴────────────────────────┘
```

- **왼쪽**: 원본(비정상 메쉬)입니다. 지워진 element 와 node 를 여기에 표시합니다.
- **오른쪽 위 / 아래**: 모델 재생성 결과 / 사람 수정 결과입니다. 지우기와 만들기가 모두 반영된
  **최종 메쉬**이고, 새로 만든 element 를 초록으로 칠합니다.

오른쪽 위아래를 비교하면 두 최종 결과가 어디서 같고 어디서 다른지 보이고, 왼쪽을 보면
각자 원본에서 무엇을 지웠는지 보입니다.

### 9.2 강조 표시

왼쪽의 '지운 element' 는 결과 메쉬에 원래 좌표 그대로 남지 않은 element 입니다. 실제로 삭제된
element 와, edge collapse 로 node 가 바뀌어 모양이 달라진 element 를 함께 셉니다. 모양이 바뀐 element
는 오른쪽 결과 화면에 새로 만든 element(초록)로 나옵니다.

| 표시 | 뜻 |
|---|---|
| 빨간 면 (왼쪽) | 모델과 사람이 **둘 다** 지운 element |
| 주황 면 (왼쪽) | **모델만** 지운 element (사람 결과에는 원래 모양 그대로 남음) |
| 보라 면 (왼쪽) | **사람만** 지운 element (모델 결과에는 원래 모양 그대로 남음) |
| 초록 면 (오른쪽) | 새로 만든 element |
| 굵은 선 | 지운 1D element (왼쪽, 위 색 규칙) / 새로 생긴 1D element (오른쪽, 진한 초록) |

node 삭제·이동은 3D 화면에 따로 표시하지 않습니다. 화면 아래 변경 목록 표와 "변경 위치로 확대…" 목록에서 볼 수 있습니다.

- 도구막대의 **원본에 표시할 삭제** 로 왼쪽 화면의 보기를 바꿉니다.
  - `비교`: 누가 지웠는지 색으로 나눕니다 (빨강 / 주황 / 보라).
  - `모델`: 모델이 지운 element 만 빨강으로 칠합니다.
  - `사람`: 사람이 지운 element 만 빨강으로 칠합니다.
- 체크박스로 각 강조를 하나씩 끄고 켤 수 있습니다. 끄면 그 element 는 회색으로 돌아갑니다.
- "변경 위치로 확대…" 목록에서 변경 하나를 고르면 세 화면이 모두 그 위치로 확대됩니다.
  "시점 초기화" 를 누르면 처음 화면으로 돌아갑니다.
- element 에 마우스를 올리면 element 번호, 내각, skew, node 번호, 누가 지웠는지 또는 상대 쪽도
  같은 변경을 했는지가 표시됩니다.
- 면적이 거의 0 인 찌그러진 element 는 면이 보이지 않고 테두리만 보입니다. 이런 element 가
  지워지는 이유가 바로 그 찌그러짐입니다.

### 9.3 화면 아래쪽

- **변경 목록**: 누가(모델/사람), 무엇을(element 삭제·생성, node 삭제·이동, 1D 삭제·생성),
  어느 element/node 에, 상대 쪽도 같은 변경을 했는지(✓/✗)를 표로 보여줍니다.
- **검사**: 메쉬 검사 위반과 경고, 모델이 적용한 연산 목록
- **전/후 지표**: 원본·모델·사람의 요소 수, 삼각형 수, 불량각 요소 수 등
- **내려받기**: 재생성된 .bdf 와 .json

### 9.4 왼쪽 메뉴

- **데이터**: "테스트 (10%)" 또는 "학습 (90%, CV 예측)". 학습 셋 결과는 각 메쉬를 그 메쉬를
  학습에 쓰지 않은 모델로 만든 결과입니다.
- **결과**: 전체 / 사람과 일치 / 사람과 다름
- **수정 종류**, **재현 가능한 쌍만**, **검색**으로 메쉬를 거를 수 있습니다.

화면은 모델을 다시 실행하지 않습니다. 채점할 때 기록해 둔 연산(어느 절점을 어디에 합쳤고
어느 삼각형 쌍을 합쳤는지)을 원본에 다시 적용해서 그립니다. 그래서 화면 결과와 채점 결과가
항상 같고, GPU 없이도 열립니다.

## 12. 한계와 다음에 할 일

1. **절점 병합의 '멈춤' 판단 개선.** 테스트 실패의 절반이 "아예 합치지 않음" 이었습니다.
   가장 효과가 클 곳입니다.
2. **편집 연산 추가.** 삼각형 1개와 사각형 1개를 다르게 다시 나누는 연산을 추가하면 상한이
   12쌍 늘어납니다. 사각형 쪼개기(5쌍), 변 위의 절점을 요소에 포함시키기(6쌍)도 후보입니다.
3. **데이터.** 테스트의 독립 표본이 24묶음뿐이라 숫자가 많이 흔들립니다. 수정 쌍이 더 생기면
   평가가 훨씬 안정됩니다.
4. **현업 확인.** 모델과 사람이 다르게 고친 메쉬 중 모델 쪽도 받아들일 만한 수정인지 현업의
   판단을 받으면, "정확 일치" 외에 실제로 쓸 만한 비율을 잴 수 있습니다.

## 부록: 설명할 때 받을 만한 질문

**Q. 정확 일치 25~40%는 낮은 것 아닌가요?**
정확 일치는 요소 하나, 1D 요소 하나까지 사람과 같아야 하는 엄격한 기준입니다. 같은 결함도
고치는 방법이 여러 가지일 수 있는데, 다르게 고쳐도 모두 틀린 것으로 셉니다. 또 이 방식의
상한이 76% 입니다. 상한 대비로 보면 재현 가능한 쌍의 절반(CV 51%)을 똑같이 맞힙니다. 품질
지표(불량각 요소 수, 심판 분류기 판정)로 보면 사람 결과에 꽤 가깝습니다.

**Q. 테스트 점수가 CV 보다 왜 낮나요?**
8.2절을 봐 주세요. 테스트 52쌍이 결함 묶음 24개에서 나와 독립 표본이 적고, '절점삭제' 쪽에
어려운 결함이 몰려 있습니다. 다른 종류의 모델도 같은 폭으로 떨어졌고, '연결만 변경' 은 CV 와
같았습니다.

**Q. GNN 을 쓴 효과가 있나요?**
1단계(절점 병합)에서는 GNN 이 조금 낫고(1단계 정확도 59% vs 52%), 2단계(삼각형 쌍)에서는
gradient boosting 이 낫습니다. 전체 정확 일치 차이는 크지 않습니다. 이번 작업에서 가장 큰
개선은 GNN 자체보다 "하나씩 반복하면서 멈출 때를 배우는" 구조에서 나왔습니다.

**Q. ext 절점을 합쳐도 괜찮나요?**
사람도 508쌍 중 48쌍에서 했기 때문에 막지 않았습니다. 대신 결과에 경고로 표시하고, 화면의
'검사' 탭에서 어떤 ext 절점이 합쳐졌는지 보여줍니다. ext 절점을 움직이는 것은 막습니다.

**Q. 심판 분류기로 채점하는 게 공정한가요?**
심판 분류기는 이 508쌍의 원본을 학습에 쓰지 않았습니다. 다만 1단계 GNN 이 그 분류기의
인코더에서 출발했기 때문에 완전히 독립적이지는 않습니다. 그래서 주 지표는 "사람 결과와의
일치" 이고, 심판 분류기 확률은 보조 지표로만 씁니다.

**Q. 왜 절점 번호로 비교하지 않나요?**
4절을 봐 주세요. 사람은 남길 절점 번호를 일정하게 고르지 않아서, 모양이 같은 결과도 번호가
다를 수 있습니다.
