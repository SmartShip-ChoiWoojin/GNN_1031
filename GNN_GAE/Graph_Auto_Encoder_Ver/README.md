# VGAE + 편집 연산으로 메쉬 재생성 (Graph_Auto_Encoder_Ver)

Bad 메쉬를 넣으면 VGAE 가 **Good 메쉬의 연결**을 예측하고, 그 예측에 가장 가까워지는
편집 연산(절점 병합, 삼각형 쌍 병합)을 하나씩 골라 적용한다. 결과는 .bdf / .json 이다.

> 이 폴더는 2026-10-23 에 새로 만들었다. 이전 실험(정상 메쉬로만 학습한 GAE 로 고칠 자리
> 찾기)은 지웠다. 코드는 git 커밋 `fca2545` 에 남아 있다.

코드가 어떤 순서로 돌아가는지는 [코드_흐름_설명.md](코드_흐름_설명.md) 에 메쉬 하나를 따라가는
예시와 함께 정리했다.

**508쌍 전부를 학습에 쓴다.** 그래서 4절의 숫자는 모두 학습 데이터에서 잰 값이고, 처음 보는
메쉬에서의 성능이 아니다. 테스트(5절)는 0918 라벨의 확실·비정상 메쉬 901개로 하며, 정답이
없어서 사람이 화면에서 보고 판정한다.

## 흐름

```
Bad 메쉬 ──▶ 절점 그래프 ──▶ VGAE ──▶ 변 확률 P_ij, 절점 확률 q_i ──▶ 편집 고르기 ──▶ 재생성 .bdf
                                     (Good 에서 i,j 가 이어져 있나 /     (meshedit 이 적용·검사)
                                      i 가 남아 있나)
```

1. **고친 곳 찾기 (정답 만들기)** — Bad 와 Good 을 좌표로 맞대어, Good 의 변을 Bad 절점 쌍으로
   옮긴다. Good 에 없는 Bad 절점은 "사라짐" 이다. (`vg_data.py`)
2. **VGAE 학습** — Bad 그래프를 넣고 Good 연결과 절점 남음을 복원하도록 학습한다. (`vg_train.py`)
3. **편집으로 바꾸기** — 예측한 연결에 가까워지도록 편집을 하나씩 적용한다. (`vg_decode.py`)

## 1. 데이터 (`vg_data.py`)

| | |
|---|---|
| 쌍 | 508쌍 전부 (학습/테스트 분할 없음) |
| 노드 | 절점. 메쉬당 중앙값 53개, 최대 76개 |
| 노드 피처 20개 | 주변 요소 품질 17개(`GNN_GAE/src/node_baseline.py` 와 같음: 붙은 요소 수, 삼각형 수, 최소·최대 내각, skew, aspect, ext 여부, 각도합, 자유변 수 등) + 메쉬 평면(PCA) 기준 위치 3개(중앙 변 길이로 나눔) |
| 엣지 | 쉘 요소의 변 |
| 엣지 피처 5개 | 길이(중앙 변 길이 대비), 공유 요소 수, 1D 요소 여부, 양끝 ext 여부, 붙은 삼각형 수 |
| 정답 | `adj_good` Good 의 변을 Bad 절점 쌍으로 옮긴 것 / `keep` Bad 절점이 Good 에 남았나 |

절점 대응은 **번호가 아니라 좌표**로 한다. 사람은 절점을 합칠 때 남길 번호를 일정하게
고르지 않았다(`GNN_GAE/메쉬_재생성_설명.md` 4절). Good 에만 있는 자리(새로 만든 절점, 옮긴
절점)는 Bad 절점으로 옮길 수 없어 정답에서 빠진다 (메쉬당 변 0.43개).

정답 통계: 사라지는 절점 메쉬당 평균 0.99개(0개인 메쉬 214), 바뀌는 변(없어짐+생김) 메쉬당
평균 6.66개.

## 2. 모델 (`vg_model.py`)

```
인코더   입력 MLP → GINE 3층 (잔차 + LayerNorm, hidden 128) → μ, log σ (잠재 32차원)
잠재     z = μ + σ·ε  (학습 때만 노이즈, 추론 때는 z = μ)
디코더   변    p(i,j 가 Good 에서 이어짐) = sigmoid(z_i · z_j + b)     ← VGAE 내적 디코더
         절점  p(i 가 Good 에 남음)        = sigmoid(w · z_i + c)
```

PyG `torch_geometric.nn.VGAE` 를 그대로 상속한다 (재매개화, KL).

일반 VGAE 와 다른 점 두 가지:

- 입력 그래프(Bad)가 아니라 **Good 의 연결**을 복원한다.
- **절점 디코더**를 더했다. 내적 디코더는 절점 집합이 고정이라 "이 절점이 없어진다" 를
  직접 말할 수 없다.

### 손실 (`vg_train.py`)

```
손실 = 변 BCE (메쉬 안 모든 절점 쌍) + 절점 BCE + β·KL      (β = 0.01)
```

| 가중치 | 값 | 이유 |
|---|---|---|
| `pos_w` | 5 | 이어진 쌍이 전체 쌍의 약 7% |
| `w_chg` | 10 | Bad 와 Good 이 다른 쌍(바뀌는 곳)이 메쉬당 6.7개뿐 |
| `w_rm` | 10 | 사라지는 절점이 메쉬당 1개꼴 |
| `w_near` | 1 또는 5 | 두 칸 이내인데 이어지지 않은 쌍. 아래 4절 참고 |

## 3. 편집으로 바꾸기 (`vg_decode.py`)

VGAE 출력은 "어느 절점 쌍이 이어져 있나" 의 확률이라 그대로 .bdf 가 될 수 없다.
그래서 **예측한 Good 연결에 가장 가까워지는 편집을 하나씩** 고른다.

```
점수(메쉬 상태) = Σ_{지금 메쉬의 변 (i,j)} logit P_ij  +  Σ_{남아 있는 절점 i} logit q_i
```

이 점수는 지금 메쉬의 연결이 VGAE 예측과 얼마나 맞는지의 로그우도와 같다(상수 차이).

1. 지금 메쉬에서 가능한 편집을 모두 나열한다.
   - 절점 병합 r→k: 변 또는 사각형 대각으로 이웃한 절점 쌍, 양방향
   - 삼각형 쌍 병합: 변을 공유하는 삼각형 쌍 (공유 변 = 없앨 엣지)
2. 편집마다 점수가 얼마나 오르는지 계산한다 (위상만 계산, 빠름).
3. 많이 오르는 편집부터 `meshedit` 으로 실제 적용해 보고, 검사(`meshedit.check`, 원본 대비)를
   통과한 첫 편집을 적용한다.
4. 점수를 올리는 편집이 없으면 멈춘다. 최대 15번.

**임계값이 없다.** 확률 0.5(logit 0)가 자연스러운 기준이 된다. 메쉬 수정과 검사는
`GNN_GAE/src/meshedit.py` 가 하므로 결과는 항상 유효한 메쉬다.

### 이 변환의 상한 — 오라클

VGAE 대신 **진짜 Good 연결**을 넣고 같은 변환을 돌린 것 (`--run oracle`):

| | 508쌍 |
|---|---:|
| 정확 일치 (요소 + 1D + 좌표) | **402 (79.1%)** |
| 요소만 일치 | 423 (83.3%) |
| 검사 위반 | 0 |

VGAE 예측이 완벽해도 79.1% 를 넘을 수 없다. 나머지는 두 편집으로 설명되지 않는 수정
(절점 추가, 좌표 이동, 다른 방식의 재배치 등)이다. 참고로 이전 재생성 모델의 상한은
76.4%(`regen_oracle.py`)였다.

### 관찰

1. **내적 디코더는 가까운 절점끼리를 다 이어져 있다고 본다.** 기본 `vgae` 가 메쉬당 76개 쌍을
   틀렸는데, 그중 72개가 두 칸 이내(같은 사각형의 대각, 이웃의 이웃) 쌍이었다. GNN 을 거치면
   가까운 절점의 z 가 비슷해지기 때문이다. 이러면 절점 r 을 어느 이웃 k 에 합쳐도 점수가
   비슷해서, 실패의 대부분(179쌍 중 118쌍)이 "병합할 절점의 위치·방향이 다름" 이었다.
   두 칸 쌍에 가중치를 주자(`--w_near 5`) 43.9% → 55.7%, 잠재 차원과 학습을 늘리자 74.4%.
2. **디코더에 Bad 연결을 더하면(`--skip`) 오히려 나빠졌다.** 그대로 둘 쌍은 잘 맞히지만
   (틀림 6.3개) 없어질 변을 덜 맞혀서, 편집을 안 하는 메쉬가 118개가 됐다. 모델이 "Bad 를
   그대로 베끼기" 에 기대게 된다.
3. 사라질 절점은 모든 설정에서 거의 다 맞힌다 (학습 데이터라서일 수 있다).
4. 검사 위반은 모든 설정에서 0 — 편집을 `meshedit` 이 적용·검사하기 때문이다.

### 인코더 conv 비교 (`--conv`, 2026-10-24)

설정은 `vgae_near_l64` 와 같게 두고(두 칸 쌍 가중 5, 잠재 64, 800 epoch) 메시지 전달 층만 바꿨다.
같은 설정도 학습마다 결과가 흔들려서 시드 0, 1 두 번씩 돌렸다. 넷 다 엣지 피처를 메시지에 쓴다.

| conv (`--tag`) | 방식 | 파라미터 | 정확 일치 시드 0 / 1 | 평균 | 오라클 402쌍 중 (평균) | 그대로여야 할 쌍 틀림 (메쉬당) |
|---|---|---:|---:|---:|---:|---:|
| GINE (`vgae_near_l64`) | 이웃 메시지(h_j + W·e_ij)의 합 → MLP | 20만 | 74.4% / 73.2% | 73.8% | 92.0% | 3.6 |
| GATv2 (`gatv2_l64`) | 이웃마다 주의 가중치(엣지 피처 포함), 가중평균 | 20만 | 57.5% / 56.5% | 57.0% | 71.2% | 9.7 |
| TransformerConv (`transformer_l64`) | 내적 주의(UniMP), 엣지 피처를 키·값에 더함 | 30만 | 69.5% / 66.7% | 68.1% | 84.8% | 5.0 |
| **NNConv** (`nnconv_l64`) | 엣지 피처로 가중치 행렬 Θ(e_ij) 를 만들어 Θ·h_j 의 평균 | **174만** | **76.4% / 76.0%** | **76.2%** | **94.8%** | **1.1** |

관찰:

1. **NNConv 가 가장 높고 GINE 이 다음이다.** 차이는 2.4%p 로, 시드 사이 흔들림(GINE 1.2%p, NNConv
   0.4%p)보다 크다. NNConv 는 "그대로여야 할 쌍을 틀림" 이 메쉬당 1.1개로 가장 적다 — 엣지마다
   다른 가중치 행렬을 쓰니 가까운 절점들의 z 가 덜 비슷해진다.
2. **다만 NNConv 는 파라미터가 GINE 의 8.6배다.** 학습 데이터 점수라서, 더 잘 일반화해서인지 더 많이
   외워서인지 이 표로는 가를 수 없다. 테스트 판정에서 같이 봐야 한다.
3. **주의(attention) 계열이 낮다.** GATv2 와 TransformerConv 는 이웃 메시지를 softmax 가중**평균**으로
   모은다. 평균은 "이웃이 몇 개인가" 를 잃는다. GINE 은 합으로 모아서 이웃 수가 남는다. 메쉬에서는
   한 절점에 모이는 요소·변의 개수가 결함과 직접 관련이 있어서 이 차이가 나온 것으로 본다 (추정).
   TransformerConv 는 자기 자신을 따로 더하는 경로(root weight)가 있어 GATv2 보다 덜 떨어진다.

## 5. 테스트 — 정답 없음, 사람이 화면에서 판정 (`vg_test.py`, `vg_app.py`)

| | |
|---|---|
| 대상 | 0918 라벨에서 **분류 = 비정상, 확실** 인 1,291개 중 학습 508쌍에 든 390개를 뺀 **901개** |
| 정답 | 없다. 사람이 고친 Good 메쉬가 없으므로 자동 채점을 하지 않는다 |
| 판정 | 사람이 화면에서 모델별 결과를 보고 좋음 / 나쁨 / 애매 + 메모를 남긴다 |

`vg_test.py` 는 901개를 7개 모델로 각각 재생성해서 저장만 한다. 표에 남기는 숫자(편집 수,
삼각형·불량각 요소 수 전후)는 참고용이고 맞고 틀림이 아니다.

**학습 메쉬와 겹침** (`overlap_train`): 패치들이 한 선박에서 잘라낸 조각이라 서로 겹친다. 테스트
메쉬의 쉘 요소 중 학습 508쌍 원본에도 (좌표가 같은 채로) 있는 요소의 비율이다. 높으면 모델이
학습에서 본 자리일 수 있다. 화면에서 이 값으로 거를 수 있다.

학습 메쉬와 겹침 분포 (901개): 하나도 안 겹침 **40개**, 조금이라도 겹침 861개, **절반 넘게 겹침 633개**.
테스트 메쉬 대부분이 학습 메쉬와 같은 자리를 포함한다. 판정을 모은 뒤에는 겹침이 낮은 메쉬만
따로 봐야 처음 보는 자리에서의 성능을 알 수 있다.

것은 아니므로 판정으로 확인해야 한다.

불량각 요소가 줄었다고 사람이 보기에 맞게 고친 것은 아니다 — 판정은 화면에서 한다.

```
┌──────────────────────────┬──────────────────────────┐
│ 변경 전 (원본)             │ 변경 후 (모델 재생성)       │

적용한 편집 (순서대로) · 모델 4개 비교 (이 메쉬)   │   판정 (좋음 / 나쁨 / 애매 + 메모)
```

- **왼쪽 사이드바**: 데이터(테스트 901 / 학습 508), 모델, 목록 거르기(편집한 메쉬만, 미판정만,
  학습 메쉬와 겹침 비율), ◀ ▶ 로 이동.
- **확대 위치**: 지운 요소나 없어진 절점을 고르면 두 화면이 같은 자리로 확대된다.
- **판정 저장**: `runs/test/judgments.csv` 에 (메쉬, 모델)마다 한 줄. 다시 저장하면 덮어쓴다.
  "저장하고 다음 메쉬로" 를 켜 두면 저장 뒤 다음 메쉬로 넘어간다.
- **학습 데이터**를 고르면 판정 대신 사람 결과와의 일치 여부를 보여 주고, "사람 결과(Good)도 보기" 로
  세 번째 화면을 켤 수 있다.
- 모델을 화면에서 돌리지 않는다. 저장된 .bdf 를 읽어 원본과 좌표로 비교해 칠한다.

## 돌려 보기

`Graph_Auto_Encoder_Ver` 폴더에서, `SHI_GNN` 환경의 파이썬으로.

```bash
python src/vg_data.py                                   # cache/pairs_node.pkl (10초)
python src/vg_train.py --tag vgae_near_l64 --w_near 5 --latent 64 --epochs 800   # GPU 약 2분
python src/vg_train.py --tag nnconv_l64 --conv nnconv --w_near 5 --latent 64 --epochs 800   # 약 3~4분
python src/vg_decode.py --run oracle                    # 변환 상한 (1~2분)
python src/vg_decode.py --run vgae_near_l64             # 재생성 → runs/<tag>/decode.csv, out/<tag>/*.bdf
python src/vg_test.py                                   # 테스트 901개 × 7개 모델 (약 20분)
python src/vg_test.py --models nnconv_l64               # 모델 하나만
```

## 파일

```
src/
  vg_paths.py    경로 + GNN_GAE/src, 부모 src 연결
  vg_data.py     Bad 절점 그래프 + Good 연결 정답 → cache/pairs_node.pkl
  vg_model.py    MeshVGAE (인코더, 변·절점 디코더), PyG Data 변환
  vg_train.py    학습 (508쌍 전부), 변·절점 단위 맞힘 보고
  vg_decode.py   VGAE 출력 → 편집 → 재생성, 사람 결과와 비교
  vg_test.py     테스트 901개를 7개 모델로 재생성 (정답 없음)
  vg_app.py      변경 전 / 변경 후 화면 + 사람 판정 기록
runs/<tag>/model.pt, edge_report.json, decode.csv      학습 데이터 결과
out/<tag>/<쌍 이름>.bdf, .json                          학습 데이터 재생성 메쉬
runs/test/test_meshes.csv                              테스트 메쉬 목록 + overlap_train
runs/test/<tag>/regen.csv                              테스트 결과 (편집, 요소·삼각형·불량각 전후)
runs/test/summary.csv                                  테스트 모델별 요약
runs/test/judgments.csv                                사람 판정
out/test/<tag>/<이름>.bdf, .json                        테스트 재생성 메쉬
cache/test_node.pkl                                    테스트 메쉬 입력 그래프
```

`decode.csv` 열: `exact` 정확 일치, `ops` 적용한 편집(`collapse:r>k`, `merge:a-b`),
`gains` 편집마다 오른 점수, `change_iou` 바뀐 요소 IoU, `rm_prec`/`rm_rec` 지운 요소 정밀도/재현율.
