# Graph AutoEncoder 실험 (Graph_Auto_Encoder_Ver)

`GNN_GAE` 의 재생성 모델은 오토인코더를 쓰지 않는다 — 편집 후보에 점수를 매겨 고른다.
이 폴더는 **Graph AutoEncoder 를 붙여 보면 무엇을 얻는지** 따로 실험하는 곳이다.

## 실험 1 — 복원 오차가 "사람이 고친 자리" 를 가리키나

**질문**: 정상 메쉬로만 GAE 를 학습하면, 복원이 잘 안 되는 요소가 곧 이상한 곳일까?
사람이 고친 508쌍에서 실제로 지운 요소를 이미 알기 때문에 바로 잴 수 있다.
508쌍은 GAE 학습에 한 번도 쓰지 않는다.

### 한 줄 결론 (2026-10-22)

**GAE 복원 오차는 고친 자리를 무작위보다 훨씬 잘 가리키지만, 학습이 필요 없는 마할라노비스
거리(요소 피처가 정상 분포에서 얼마나 먼가)를 넘지 못했다.** 그래프 문맥(메시지 전달)을
빼도 성능이 같거나 오히려 나았고, GAE 점수를 마할라노비스에 더해도 좋아지지 않았다.
→ 이 데이터에서 "고칠 자리" 는 **요소 자기 생김새**로 거의 결정되고, 이웃을 보고 복원하는
GAE 가 더해 주는 정보가 없다.

### 요소 단위 — 메쉬마다 "사람이 지운 요소를 상위 k 안에 찍었나" (504 메쉬)

|---|---|---|---|

### 메쉬 단위 — "고쳐야 하는 메쉬인가" (검증 정상 205 vs 쌍 원본 508, AUC)

상위 3 요소 점수 평균 기준: 최소내각 0.897 / 마할라노비스 0.896 / GAE 최고 0.889 (`ae_nograph:xr`),
그래프 있는 GAE 최고 0.886 (`mae:rz`).

### 왜 GAE 가 이기지 못했나 (관찰)

1. **가림 복원은 '동네' 를 찾는다.** `mae` 의 1위 요소는 43% 가 정답, 23% 가 정답 바로 옆이다.
   결함 요소 주변도 같이 찌그러져 있어서, 이웃을 보고 복원하면 결함이 동네 전체로 번진다.
2. **잔차를 그대로 평균하면 손해다.** 법선 방향·면적처럼 원래 맞히기 어려운 피처의 오차가
   점수를 지배한다. 정상 잔차 분포로 표준화(`rz`)하면 top-1 이 33% → 43% 로 오른다.
3. **인접 복원은 거의 쓸모가 없다** (top-1 18%). 요소 사이 연결은 결함이 있어도 대부분 그대로다.
4. **그래프를 빼도 같다** (`ae` vs `ae_nograph`). 피처 복원 오차는 사실상 "이 요소가 정상 요소
   분포에서 얼마나 드문가" 이고, 그건 마할라노비스가 이미 잰다.
5. **보탬도 안 된다.** 메쉬 안 순위를 평균해 마할라노비스와 섞으면: + `ae:xr` 53.4%, + `mae:rz` 51.5%
   (단독 53.8%). 반면 + 삼각형 규칙은 55.2% / top-3 79.8% 로 오른다.

### 남은 의미 / 다음

- 비지도로 "고칠 동네" 를 66~74% 맞히는 건 쓸 만하다. 다만 그 일은 마할라노비스 한 줄로 된다.
- 인코더 사전학습(원래 계획한 2번)도 기대를 낮춰야 한다. GAE 가 배운 표현이 요소 하나의
  드묾 이상을 담는다는 증거가 이번에 나오지 않았다. 해 본다면 `mae` 인코더를 재생성 모델의
  `encoder_run` 자리에 넣고 기존 지표(CV 39.7% / 테스트 25.0%)와 비교하면 된다.
- 지도학습 GBM(77%)과의 차이가 크다. 정답이 508쌍 있는 지금은 비지도보다 지도학습이 맞는 길이다.

한 선박에서 잘라낸 조각이라 서로 겹친다. 무작위로 나누면 검증 정상이 학습 정상과 거의
같은 패치가 된다.

## 모델 (`src/ae_model.py`)

| 이름 | 방식 | 이상 점수 |
|---|---|---|
| `mae` | 요소 30% 의 피처를 [MASK] 로 바꾸고 이웃만 보고 복원 (GraphMAE 식). 가린 요소에 붙은 엣지의 '두 요소 비교' 칸(면적비·최소내각 차·같은 타입)은 지운다 — 답을 흘리기 때문 | 요소를 돌아가며 가리고 잰 복원 오차 |
| `ae` | 인코더 → 16차원 잠재벡터 → 자기 피처 복원 + 잠재벡터 내적으로 인접 복원 (고전 GAE / DOMINANT 식) | 피처 오차, 인접 오차, 둘의 합 |
| `ae_nograph` | `ae` 에서 메시지 전달 층을 뺀 것 (요소 하나만 봄) | 그래프 문맥이 값을 하는지 보는 대조군 |

인코더는 부모 `MeshGNN` 과 같은 GINE 3층(잔차, hidden 128). 처음부터 학습한다.

점수 변형:
- `feat` — 피처 잔차 제곱 평균 그대로
- `rz` — 잔차 벡터의 마할라노비스 거리 (학습 정상 메쉬의 잔차 분포로 적합)
- `xr` — [피처, 잔차] 를 이어 붙인 마할라노비스
- `sum` (`ae` 만) — 피처 오차 + 인접 오차 (각각 정상 분포로 표준화)

## 돌려 보기

`Graph_Auto_Encoder_Ver` 폴더에서, `SHI_GNN` 환경의 파이썬으로.

```bash
python src/ae_data.py                          # 캐시 (정상 분할 + 쌍 원본 그래프·정답)
python src/ae_train.py --mode mae --tag mae    # 각 1~3분 (GPU)
python src/ae_train.py --mode ae  --tag ae
python src/ae_train.py --mode ae  --tag ae_nograph --layers 0
python src/ae_eval.py --runs mae ae ae_nograph # 채점 → runs/eval_summary.csv
```

## 파일

```
src/
  ae_paths.py   경로 + GNN_GAE/src, 부모 src 연결
  ae_data.py    정상 메쉬 분할, 쌍 원본 그래프 + 요소별 정답 (cache/)
  ae_model.py   GraphAE (mae / ae)
  ae_train.py   정상 메쉬로만 학습 → runs/<tag>/model.pt
  ae_eval.py    채점: 요소 top-k·AUC, 절점 top-k(지도학습 GBM 과 비교), 메쉬 단위 AUC
runs/<tag>/pair_scores_<점수>.pkl   쌍 원본의 요소별 점수 (화면용)
```
