## 1. 실행 순서

`Graph_Auto_Encoder_Ver` 폴더에서 `SHI_GNN` 환경의 파이썬으로 실행한다.

```bash
python src/vg_data.py                                                   # ① 데이터 (10초)
python src/vg_train.py --tag vgae_near_l64 --w_near 5 --latent 64 --epochs 800   # ② 학습 (GPU 약 2분)
python src/vg_decode.py --run oracle                                    # ③-a 변환 상한 (1~2분)
python src/vg_decode.py --run vgae_near_l64                             # ③-b 재생성 (1~2분)
```

①은 한 번만 하면 된다. ②와 ③은 `--tag` / `--run` 이름으로 결과 폴더가 나뉜다.
VS Code 의 실행 및 디버그 메뉴에도 ②, ③-b 를 짧게 돌리는 항목이 있다
("VGAE 학습 …", "VGAE 재생성 …").

## 2. `vg_paths.py` — 경로와 import

```
Graph_Auto_Encoder_Ver/src   ← 이 폴더의 코드 (vg_*.py)
GNN_GAE/src                  ← 쌍 불러오기(pairs), 편집 연산(meshedit), 메쉬 비교(meshdiff), 절점 피처(node_baseline)
GNN_Claude/src               ← bdf 파싱(bdf_io), 메쉬 위상(meshrep), 품질 계산(features)
```

`import vg_paths` 를 하면 `GNN_GAE/src` 가 `sys.path` 에 들어가고, 이어서 `gae_paths` 를 import

import** 한다. 이것은 실행할 때만 일어나는 일이라, VS Code(Pylance)는
`.vscode/settings.json` 의 `python.analysis.extraPaths` 로 같은 경로를 따로 알려 줘야 한다.

|---|---|

| `RUNS_DIR` | `runs/` — 모델, 결과 표 |
| `OUT_DIR` | `out/` — 재생성 .bdf/.json |

## 3. `vg_data.py` — 절점 그래프와 정답 만들기

`main()` 이 508쌍을 차례로 `load_pair()`(GNN_GAE/src/pairs.py)로 불러와 `build_one()` 에 넘긴다.

### 3.1 `build_one(pair)` 의 순서

```
1. rep = MeshRep(bad)                          메쉬 위상 (절점↔요소, 변↔요소)
2. ids, Xq = node_rows(rep)                    절점 id 목록(정렬됨) + 품질 피처 17개
3. X = [Xq, local_xyz(P, 중앙 변 길이)]        + 위치 3개 → 절점 피처 20개
4. 입력 엣지 = Bad 쉘 요소의 변                 엣지 피처 5개
5. 정답 keep     = Bad 절점의 좌표가 Good 에 있나
   정답 adj_good = Good 의 변을 좌표로 Bad 절점 쌍에 옮긴 것
```

- **절점 피처 17개**는 `GNN_GAE/src/node_baseline.py` 의 `node_rows()` 를 그대로 쓴다:
  붙은 요소 수, 붙은 1D 수, 붙은 삼각형 수와 비율, 주변 최소·최대 내각, skew, aspect,
  불량 요소 수, ext 여부, 각도합 − 360°, 자유변 수, 비매니폴드 변 수, 최대 이면각,
  면적비, 붙은 변 길이의 최소·최대(중앙 변 길이 대비).
- **위치 3개** (`local_xyz`): 메쉬 좌표에서 평균을 빼고 PCA 로 돌린 뒤 중앙 변 길이로 나눈 값.
  메쉬가 어느 방향(갑판·격벽)에 있든 같은 기준이 된다. PCA 축의 부호는 3차 모멘트로 고정한다.
  내적 디코더가 "가까운 절점" 과 "이어진 절점" 을 구분하려면 위치 정보가 필요하다.
- **엣지 피처 5개** (`EDGE_FEATS`): 길이(중앙 변 길이 대비), 그 변을 쓰는 요소 수(1=자유변),
  1D 요소가 올라타 있나, 양끝이 모두 ext 인가, 그 변을 쓰는 삼각형 수.

### 3.2 정답을 좌표로 옮기는 이유

사람은 절점을 합칠 때 남길 **번호**를 일정하게 고르지 않았다. 어떤 때는 흡수된 절점 번호를
남기고, 어떤 때는 흡수한 절점 번호를 남겼다. 하지만 결과 메쉬의 **모양**은 같다. 그래서 번호
대신 좌표(`meshdiff.pkey`, 1e-3 mm 단위로 반올림)로 Good 절점을 Bad 절점에 대응시킨다.

```python
pos  = {pkey(Bad 좌표): Bad 절점 인덱스}
gmap = {Good 절점: pos.get(pkey(Good 좌표))}      # 대응 없으면 None
keep[i]  = Bad 절점 i 의 좌표가 Good 요소에 쓰인 좌표 중에 있나
adj_good = {(gmap[a], gmap[b]) : Good 의 변 (a,b), 둘 다 대응될 때}
```

Good 에만 있는 자리(새로 만든 절점, 옮긴 절점)는 대응이 없어 정답에서 빠진다
(`unmapped_good_edges`, 메쉬당 평균 0.43개 변).

### 3.3 저장되는 것 (쌍 하나 = dict 하나)

| 키 | 모양 | 뜻 |
|---|---|---|
| `name` | str | 쌍 이름 |
| `ids` | list[int] (n) | Bad 절점 번호, 정렬됨. 이후 모든 행 순서의 기준 |
| `x` | (n, 20) float32 | 절점 피처 |
| `edge_index` | (2, E) int64 | 입력 엣지 (한 방향만, i<j) |
| `edge_attr` | (E, 5) float32 | 엣지 피처 |
| `keep` | (n,) float32 | 1 = Good 에 남음, 0 = 사라짐 |
| `adj_good` | list[(i, j)] | Good 의 변 (Bad 인덱스, i<j) |
| `adj_bad` | list[(i, j)] | Bad 의 변 |
| `before`, `after` | RawMesh | 원본 메쉬 (편집·비교·.bdf 쓰기에 다시 쓴다) |

## 4. `vg_model.py` — VGAE

### 4.1 `to_data(d, nx, ne)` — 쌍 하나를 PyG `Data` 로

```
x           (n, 20)       절점 피처, z-score (nx)
edge_index  (2, 2E)       입력 엣지를 양방향으로
edge_attr   (2E, 5)       엣지 피처, z-score (ne)
pair_index  (2, n(n-1)/2) 메쉬 안 모든 절점 쌍 i<j  ← 디코더가 채점할 대상
y_adj       (n(n-1)/2,)   정답: 그 쌍이 Good 에서 이어져 있나
a_bad       (n(n-1)/2,)   그 쌍이 Bad 에서 이어져 있나
near        (n(n-1)/2,)   Bad 에서 두 칸 이내인데 이어지지 않은 쌍 (손실 가중용)
y_keep      (n,)          정답: 절점이 남나
```

- 절점이 53개면 쌍은 1,378개다. 메쉬가 작아서 **모든 쌍**을 채점해도 부담이 없다
  (일반 VGAE 처럼 음성 쌍을 뽑아 쓸 필요가 없다).
- `near` 는 `A·A > 0` 이면서 `A = 0` 인 쌍이다 (A = Bad 인접행렬). 같은 사각형의 대각,
  이웃의 이웃이 여기에 든다.
- 이름에 `index` 가 들어간 속성은 PyG 가 배치로 묶을 때 절점 번호만큼 자동으로 밀어 준다.
  그래서 `pair_index` 는 배치에서도 올바른 절점을 가리킨다.

### 4.2 `Encoder` — 절점마다 μ, log σ

```
h = MLP(x)                         20 → 128
e = MLP(edge_attr)                 5  → 128
반복 3번:  h = h + Dropout(ReLU(LayerNorm(GINEConv(h, edge_index, e))))     잔차 연결
μ      = Linear(h)                 128 → latent (32 또는 64)
log σ  = Linear(h), 위로 10 에서 자름
```

`GINEConv` 자리는 `--conv` 로 바꿀 수 있다 (`make_conv()`, `CONV_KINDS`). 넷 다 엣지 벡터 `e` 를 받는다.

| `--conv` | PyG 클래스 | 메시지 |
|---|---|---|
| `gine` (기본) | `GINEConv` | `MLP((1+ε)h_i + Σ_j ReLU(h_j + W e_ij))` |
| `gatv2` | `GATv2Conv` (head 4) | 이웃마다 주의 가중치 α_ij (h_i, h_j, e_ij 로 계산), 가중평균 |
| `transformer` | `TransformerConv` (head 4) | α_ij = softmax(q_i · (k_j + W_e e_ij)), 메시지 = v_j + W_e e_ij |
| `nnconv` | `NNConv` (평균 집계) | 엣지 벡터 → MLP → 128×128 행렬 Θ(e_ij), 메시지 = Θ(e_ij) h_j |

옛 체크포인트(`cfg` 에 `conv` 가 없는 것)는 `load_model` 이 GINE 으로 읽는다.

### 4.3 `MeshVGAE` — PyG `VGAE` 를 상속

```python
z = self.encode(x, edge_index, edge_attr)     # VGAE.encode: 학습 중이면 μ + σ·ε, 평가 중이면 μ
pair_logit = (z[i] * z[j]).sum(-1) + b        # 내적 디코더 (+ --skip 이면 α·a_bad)
keep_logit = Linear(z)                        # 절점 디코더
```

- `VGAE.encode` 는 μ, log σ 를 내부에 저장하고, `kl_loss()` 가 그것으로 KL 을 계산한다.
- **절점 디코더를 따로 둔 이유**: 내적 디코더는 절점 집합이 고정이라 "이 절점이 없어진다" 를
  직접 말할 수 없다.
- `--skip` 은 디코더에 Bad 연결을 더하는 선택지다. 실험해 보니 나빠졌다 (README 4절).

### 4.4 `Norm`

학습 데이터 전체로 평균·표준편차를 구해 z-score 한다. 표준편차가 0 인 열은 1 로 둔다.
`model.pt` 에 같이 저장해서 디코딩 때 똑같이 쓴다.

## 5. `vg_train.py` — 학습

### 5.1 `main()` 순서

```
D = load_data()                         pairs_node.pkl (508쌍)
nx, ne = make_norms(D)                  피처 정규화 기준
data = [to_data(d, nx, ne) for d in D]
model = MeshVGAE(...)
Adam(lr 1e-3, weight decay 1e-5) + CosineAnnealing, 배치 32, 그래디언트 클리핑 5
epoch 마다: 모든 배치에 대해 loss_fn → backward → step
끝나면: predict → edge_report 출력 → model.pt, edge_report.json 저장
```

**분할이 없다.** 508쌍 전부를 학습에 쓴다(테스트는 나중에). 조기종료도 없이 정해진
epoch 만큼 돈다.

### 5.2 `loss_fn` — 손실

```
변 손실:   쌍마다 BCE(pair_logit, y_adj) × w, 가중평균
   w = (y_adj=1 ? pos_w : 1)              이어진 쌍은 약 7% 뿐                  pos_w = 5
     × (y_adj≠a_bad ? w_chg : 1)          바뀌는 쌍은 메쉬당 6.7개뿐             w_chg = 10
     × (near 이고 y_adj=0 ? w_near : 1)   내적 디코더가 헷갈리는 두 칸 쌍        w_near = 1 또는 5
절점 손실: BCE(keep_logit, y_keep) × (사라지는 절점이면 w_rm), 가중평균        w_rm = 10
KL:        model.kl_loss() (절점 평균)                                        β = 0.01

손실 = 변 손실 + 절점 손실 + β·KL
```

`w_near` 가 중요했다. 기본(1)으로 학습한 모델은 메쉬당 76개 쌍을 잘못 "이어짐" 으로
봤는데, 그중 72개가 두 칸 쌍이었다. GNN 을 거치면 가까운 절점의 z 가 비슷해져서 내적이
커지기 때문이다. 이러면 3절의 편집 고르기에서 절점을 **어느 이웃에** 합칠지 구분이 안 된다.

### 5.3 `predict` / `edge_report`

- `predict`: `model.eval()` 상태(z = μ, 노이즈 없음)로 쌍마다 `(변 확률 배열, 절점 확률 배열)`
  을 돌려준다. 배열 순서는 `to_data` 의 `pair_index` 순서(= `np.triu_indices(n, 1)`)와 `ids` 순서다.
- `edge_report`: 확률 0.5 기준으로 없어질 변·새로 생길 변·그대로여야 할 쌍·사라질 절점을
  얼마나 맞혔는지 센다. 편집 전, VGAE 출력 자체의 성적이다.

### 5.4 `load_model(run, device)`

`model.pt` 를 읽어 같은 구조로 모델을 만들고, 저장된 정규화 기준(`nx`, `ne`)과 함께 돌려준다.
`vg_decode.py` 가 쓴다.

## 6. `vg_decode.py` — VGAE 출력을 편집으로

### 6.1 왜 바로 .bdf 가 안 되나

VGAE 가 내는 것은 "절점 쌍이 이어져 있을 확률" 표다. 그것만으로는 어느 절점 넷이 사각형
요소 하나인지, 1D 요소는 어디로 가는지, 요소가 뒤집히지 않는지 알 수 없다. 그래서 확률표를
**목표**로 삼고, 실제 수정은 검증된 편집 연산(`GNN_GAE/src/meshedit.py`)으로 한다.

### 6.2 점수 — "지금 메쉬가 VGAE 예측과 얼마나 맞나"

```
logit 표:  L[i, j] = log(P_ij / (1 − P_ij))       Lq[i] = log(q_i / (1 − q_i))      (확률은 [1e-4, 1−1e-4] 로 자름)

점수(메쉬) = Σ_{메쉬의 변 (i,j)} L[i, j]  +  Σ_{남아 있는 절점 i} Lq[i]
```

이것은 "지금 메쉬의 연결과 절점이 VGAE 예측 분포에서 나올 로그우도" 에서 상수를 뺀 것과
같다. 그래서 **확률 0.5 보다 높은 변을 가지면 점수가 오르고, 낮은 변을 가지면 내린다.**
편집 하나가 점수를 얼마나 바꾸는지는 그 편집으로 바뀌는 변과 절점만 보면 된다.

| 편집 | 점수 증가 |
|---|---|
| 삼각형 쌍 병합 (공유 변 e 제거) | `−L[e]` |
| 절점 병합 r→k | `Σ 새로 생긴 변의 L − Σ 없어진 변의 L − Lq[r]` |

절점 병합 뒤 어떤 변이 생기고 없어지는지는 `_collapsed_shells()` 가 **검사 없이 위상만**
계산한다. 쉘마다 r 을 k 로 바꾸고 `meshedit._compact` 로 정리하며, 찌그러진 요소와 겹친
요소를 지운다. `meshedit.collapse_many` 와 같은 규칙이다.

### 6.3 `regenerate(bad, ids, L, Lq)` — 편집을 하나씩

```
m = bad 의 사본
최대 15번 반복:
    후보 = []
    삼각형 쌍 병합 후보  ← merge_candidates(m, drop_lines=True) 중 막히지 않은 것
    절점 병합 후보       ← collapse_pairs(m)  (변·사각형 대각으로 이웃한 쌍, 양방향)
    후보마다 점수 증가 계산 (6.2)
    점수 증가가 큰 순서로:
        증가 ≤ 0 이면 → 그만 (더 맞아지는 편집이 없다)
        m 의 사본에 실제로 적용  (collapse_edge / merge_tris)
            EditError(접힘, 오목, 면적 0, 비매니폴드 증가, 1D 이탈 …) → 다음 후보
        check(사본, bad, regen=True) 위반 → 다음 후보   (원본 대비 누적 면적 5% 등)
        통과 → 이 편집을 채택, m = 사본, 다음 반복
    채택한 편집이 없으면 멈춤
돌려줌: (결과 메쉬, 편집 목록, 편집마다 점수 증가)
```

- **임계값이 없다.** "점수가 오르면 한다" 가 곧 확률 0.5 기준이다.
- 위상 계산(빠름)으로 순위를 먼저 매기고, 비싼 실제 적용·검사는 위에서부터 통과할 때까지만 한다.
- 절점 병합은 **방향**이 다르면 다른 후보다. r→k 는 r 이 사라지고 k 가 제자리에 남는다.
  좌표는 하나도 움직이지 않는다.
- 1D 요소가 올라탄 변을 삼각형 쌍 병합으로 없애면 그 1D 도 함께 지운다(`drop_lines=True`).
  사람도 손댄 구역 1D 의 19% 를 지웠다.

### 6.4 `--run oracle` — 변환기의 상한

`oracle_tables()` 는 VGAE 대신 **진짜 정답**으로 logit 표를 만든다
(Good 에 있는 변 +8, 없는 쌍 −8, 남는 절점 +8, 사라지는 절점 −8). 같은 `regenerate` 를 돌리면
"VGAE 가 완벽할 때 이 변환으로 몇 쌍을 재현하나" 가 나온다. 결과는 508쌍 중 402쌍(79.1%)이다.
모델 결과를 볼 때 이 402쌍만 따로 센 값도 출력한다 (`runs/oracle/decode.csv` 를 읽는다).

### 6.5 `main()` 과 출력

```
D 읽기 → (oracle 이면 oracle_tables, 아니면 load_model → predict → logit_tables)
쌍마다: regenerate → compare(bad, 결과, good) → 행 하나
        결과를 out/<run>/<이름>.bdf, .json 으로 저장 (--no_bdf 면 생략)
runs/<run>/decode.csv 저장 (--limit N 이면 decode_limitN.csv — 전체 결과를 덮어쓰지 않게)
요약 출력
```

`compare()` (GNN_GAE/src/meshdiff.py)는 **좌표로** 비교한다. 요소 하나를 "꼭짓점 좌표의
집합" 으로 보고 Bad·결과·Good 을 맞댄다.

| `decode.csv` 열 | 뜻 |
|---|---|
| `exact` | 요소, 1D, 절점 좌표가 모두 사람 결과와 같음 (주 지표) |
| `exact_shells` | 쉘 요소만 같음 |
| `did_nothing` | 편집을 하나도 안 함 |
| `valid` | `meshedit.check` 위반 없음 |
| `n_collapse`, `n_merge` | 절점 병합 수, 삼각형 쌍 병합 수 |
| `ops` | 적용한 편집, 순서대로. `collapse:r>k`, `merge:a-b` |
| `gains` | 편집마다 점수 증가 |
| `change_iou` | 바뀐 요소(지운 것 + 만든 것)가 사람과 얼마나 겹치나 |
| `rm_prec`, `rm_rec` | 지운 요소의 정밀도, 재현율 |

## 7. 예시 — `SN2592_FWD_Clean_0199` 를 따라가기

모델은 `vgae_near_l64` (두 칸 쌍 가중 5, 잠재 64, 800 epoch).
**이 쌍도 학습에 쓴 쌍이다.** 작동 방식을 보여 주는 예시이지 성능 증거가 아니다.

### 7.1 데이터

| | |
|---|---|
| Bad 메쉬 | 요소 31개 (삼각형 13개), 절점 33개 |
| `x` | (33, 20) |
| `edge_index` | (2, 126) — 변 63개 × 양방향 |
| `pair_index` | (2, 528) — 33×32/2 쌍 |
| Bad 의 변 / Good 의 변 | 63 / 56 |
| 두 칸 이내인데 안 이어진 쌍 (`near`) | 131 |

사람이 한 일을 정답으로 옮기면:

- 사라지는 절점: **20378, 22813**
- 없어지는 변 11개: 20378 과 22813 에 붙은 변 전부(10개) + `(12511, 12514)`
- 생기는 변 4개: `(12497, 25877)`, `(20377, 25877)`, `(12491, 25875)`, `(22812, 25875)`

즉 사람은 20378 을 25877 에, 22813 을 25875 에 합치고, 12511–12514 변을 사이에 둔 삼각형 두 개를
사각형 하나로 합쳤다.

### 7.2 VGAE 출력

| 쌍 / 절점 | 정답 | VGAE 확률 |
|---|---|---:|
| 없어질 변 11개 | 0 | 0.000 ~ 0.031 |
| 생길 변 4개 | 1 | 0.996 ~ 0.999 |
| 절점 20378, 22813 | 사라짐 | q = 0.000 |
| 나머지 절점 | 남음 | q ≥ 0.998 |

### 7.3 편집 고르기 — 첫 단계

첫 단계 후보는 절점 병합 198개, 삼각형 쌍 병합 2개, 합쳐서 200개다. 점수 증가가 양수인 것은
17개뿐이다. 상위 후보:

| 후보 | 점수 증가 | = 생긴 변 L 합 | + 없어진 변 −L 합 | + 사라진 절점 −Lq |
|---|---:|---:|---:|---:|
| **20378 → 25877** | **61.00** | 13.92 (변 2개) | 37.87 (변 5개) | 9.21 |
| 22813 → 25875 | 51.81 | 12.70 | 29.89 | 9.21 |
| 20378 → 12497 | 46.80 | −0.29 (변 4개) | 37.87 | 9.21 |
| 20378 → 20377 | 42.20 | −4.89 | 37.87 | 9.21 |
| 20378 → 25876 | 39.39 | −7.70 | 37.87 | 9.21 |
| 25877 → 20378 (방향 반대) | **−8.21** | | | |

읽는 법:

- 20378 을 **어디에 합치든** 20378 의 변 5개가 없어지고 20378 이 사라지는 것은 같다
  (37.87 + 9.21). 후보를 가르는 것은 **새로 생기는 변**이다. 25877 에 합치면 생기는 두 변이
  VGAE 가 "이어질 것" 이라고 본 변이라 +13.92 를 얻는다. 다른 이웃에 합치면 VGAE 가
  "안 이어질 것" 이라고 본 변이 생겨 점수가 깎인다.
- 방향을 바꾸면(25877 → 20378) VGAE 가 "남는다" 고 본 25877 이 사라지고, 25877 의 변들이
  없어져서 −8.21 이다.
- 이 구분이 되려면 두 칸 이내 쌍(여기서는 20378 의 다른 이웃과 25877 의 이웃)에 대한 예측이
  정확해야 한다. 5.2 의 `w_near` 가 그 역할을 한다.

20378 → 25877 이 검사를 통과해 채택된다.

### 7.4 이후 단계와 결과

| 단계 | 채택한 편집 | 점수 증가 |
|---|---|---:|
| 1 | 절점 병합 20378 → 25877 | 61.00 |
| 2 | 절점 병합 22813 → 25875 | 51.81 |
| 3 | 삼각형 쌍 병합, 공유 변 12511–12514 | 3.43 |
| 4 | 점수를 올리는 편집 없음 → 멈춤 | |

결과 메쉬는 요소 26개(삼각형 7개)이고, 사람 결과와 **정확 일치**한다.
3단계의 증가가 작은 이유는 그 변의 확률이 0.031 이라 logit 이 약 −3.4 이기 때문이다. 0.5 를
넘었다면 그 변을 남기고 멈췄을 것이다.

## 9. 주의할 점

- **모든 숫자가 학습 데이터 점수다.** 508쌍 전부를 학습에 썼다. 처음 보는 메쉬에서의 성능은
  아직 모른다. 7절 예시도 학습에 쓴 쌍이다.
- **번호가 아니라 좌표로 비교한다.** 결과 .bdf 의 절점 번호가 사람 결과와 달라도 모양이 같으면
  정확 일치다.
- **이 방식으로는 할 수 없는 수정**: 절점 추가, 절점 좌표 이동, 두 편집으로 설명되지 않는
  재배치(사각형 쪼개기 등). 오라클이 재현 못 하는 106쌍이 이런 경우다.
- `vg_decode.py --limit N` 은 `decode_limitN.csv` 에 저장한다. 전체 결과 `decode.csv` 는 그대로 남는다.
- VS Code 에서 `gae_paths` 등을 못 찾는다고 나오면 `.vscode/settings.json` 의
  `python.analysis.extraPaths` 를 확인한다 (2절).
