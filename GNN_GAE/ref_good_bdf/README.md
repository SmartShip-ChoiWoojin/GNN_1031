# good 참고 학습 (ref_good_bdf)

**질문**: 재생성 모델을 학습할 때 good(사람이 고친 `.bdf`)을 지금보다 더 많이 참고하면
나아지나?

기존 학습([../src/regen_train.py](../src/regen_train.py))은 good 에서 **"후보 중 어느 것이 사람이
한 병합인가"** 하나만 뽑아 쓴다. 메쉬 하나에 정답 후보는 1~3개뿐이라 supervision 이 sparse 하다.
이 폴더는 good 과 원본을 요소·절점마다 비교한 **dense label** 을 auxiliary task 로 더 학습시킨다 (multi-task learning).

> good 은 **학습 때만** 쓴다. 실제로 고칠 때는 good 이 없다(그게 정답이니까). auxiliary head 는
> 추론에서 쓰지 않고, 후보 logit 과 STOP logit 은 기존과 똑같이 원본만 보고 낸다.

## 결과 (2026-10-22, 학습 셋 456쌍 out-of-fold)

**정확일치는 나아지지 않았다** — 기준 39.0% / good 참고 39.5%(가중치 0.5) / 38.8%(1.0).
같은 설정을 다시 돌린 것끼리도(기존 `regen_final` 39.7% vs 이번 `base` 39.0%) 메쉬 25개가
뒤바뀌는 잡음 수준이고, good 참고가 바꾼 메쉬도 그 정도다.

다만 **행동은 바뀌었다** — 병합을 더 적극적으로 한다.

| | regen_final (기존) | base (aux 0) | **aux05** | aux10 |
|---|---|---|---|---|
| CV 정확일치 | 39.7% | 39.0% | **39.5%** | 38.8% |
| 재현 가능한 쌍 중 정확일치 | 51.0% | 50.4% | 50.7% | 49.9% |
| 바뀐 요소 IoU | 0.595 | 0.583 | **0.598** | 0.593 |
| 병합 필요한 메쉬(181) 중 1단계 정답 | 42.0% | 39.2% | **44.8%** | 42.0% |
| 병합 필요한데 **아예 안 함** | 27.1% | 30.9% | 24.9% | **23.8%** |
| 병합 불필요한 메쉬(168)인데 **더 함** | 13.1% | **10.1%** | 14.3% | 16.7% |
| 심판 비정상률 (재생성 결과) | 28.1% | 29.8% | 27.4% | **26.8%** |
| '연결만 변경' 정확일치 | 60.8% | **62.5%** | 59.1% | 58.0% |
| '절점삭제' 정확일치 | 30.4% | 27.9% | **31.2%** | 30.8% |

| 비교 | 새로 맞힘 | 새로 틀림 | 부호검정 p |
|---|---|---|---|
| aux05 vs base | 13 | 11 | 0.84 |
| aux10 vs base | 14 | 15 | 1.00 |
| base vs regen_final (같은 설정 재실행) | 11 | 14 | — |

### 해석

- good 과의 차이(어디가 바뀔 곳인가)를 직접 배우자 **"고칠 곳이 있는데 멈추는"** 실수가
  31% → 24~25% 로 줄었다. 노린 효과는 나왔다.
- 그 대가로 **"고칠 곳이 없는데 손대는"** 실수가 10% → 14~17% 로 늘었다. 인코더가 '바뀔
  곳' 을 더 민감하게 보게 되면서 종료 조건(STOP logit 대비 margin)도 함께 느슨해졌다.
- 둘이 상쇄되어 정확일치는 그대로다. 테스트 셋은 열지 않았다 (개선이 확인될 때 한 번만 연다).

### 다음에 해 볼 것

- 이득(조기 종료 감소)만 남기려면 **종료 조건을 따로 강화**해야 한다. 예: "이 메쉬에 병합이 필요한가"
  를 메쉬 단위로 따로 맞히는 분류기를 두고, 그게 '아니오' 면 1단계를 건너뛴다. good 참고
  인코더는 바뀔 곳을 찾는 데, 별도 분류기는 손댈지 말지에 쓰는 분업이다.
- 보조 라벨을 1단계에 필요한 것만으로 좁히기 — 지금 요소 라벨에는 2단계(삼각형 병합)로
  바뀔 요소도 들어 있어서, 1단계 모델이 '아직 바뀔 곳이 남았다' 고 느끼게 만들 수 있다.

## 무엇을 바꿨나

1단계(절점 병합) GNN 인코더 위에 auxiliary head 두 개(절점·요소 binary classifier)를 달고, 후보 손실과 함께 학습한다.

| 보조 과제 | 정답 (good 과 비교) | 입력 |
|---|---|---|
| 절점 | 이 절점의 **자리**가 good 에 없나 (병합으로 사라질 자리) | 절점에 붙은 요소 임베딩의 평균·최대 |
| 요소 | 이 요소(꼭짓점 좌표 집합)가 good 에 없나 (지워지거나 모양이 바뀔 요소) | 요소 임베딩 |

손실 = 후보 손실(listwise) + `aux_w` × (절점 BCE + 요소 BCE), 양성 가중치 4.
중간 상태(사람 병합을 일부 적용한 메쉬)에도 그 상태와 good 을 비교해 라벨을 단다.
좌표로 비교한다 — 사람은 남길 절점 번호를 일정하게 고르지 않는다(`meshdiff.py`).

라벨 점검(학습 셋 25개): 요소 라벨이 `meshdiff` 의 '지운 요소' 와 25/25 일치, 정답 병합의
remove 절점은 전부 1. 양성 비율은 절점 2.5% / 요소 10.7%.

나머지(분할, 5-fold, 중간 상태, 임계값 고르기, 2단계 GBM, 배포 앙상블)는 기존과 같다.
비교 기준도 같은 코드 경로에서 `aux_w=0` 으로 다시 돌렸다 — GPU 비결정성 때문에 같은 설정도
CV 가 ±2%p 흔들려서, 기존 `regen_final` 숫자만 놓고 비교하면 잡음과 구분이 안 된다.

## 돌려 보기

`ref_good_bdf` 폴더에서, `SHI_GNN` 환경의 파이썬으로. 각 25~40분 (GPU).

```bash
python src/rg_train.py --aux-w 0   --tag base  --loss list --scorer2 gbm --seeds 0,1,2
python src/rg_train.py --aux-w 0.5 --tag aux05 --loss list --scorer2 gbm --seeds 0,1,2
python src/rg_eval.py --run runs/regen_aux05 --split cv     # 학습 셋 out-of-fold 채점
python src/rg_eval.py --run runs/regen_aux05                # 테스트 셋 — 마지막에 한 번만
streamlit run GNN_GAE/ref_good_bdf/src/app_regen_ref.py     # 화면 (GNN_Claude 에서)
```

화면은 기존 `app_regen.py` 그대로이고, 목록에 기존 `GNN_GAE/runs/regen_*` 와 이 폴더의
`runs/regen_*` 가 함께 뜬다. 개선 중에는 "train"(CV) 화면으로 본다.

```

  rg_train.py       기존 regen_train.py 에 위 두 가지만 끼워 돌린다
  rg_eval.py        기존 regen_eval.py 를 이 폴더 실행에 대해
  app_regen_ref.py  기존 화면 + 두 폴더 실행 목록
runs/regen_<tag>/   학습 결과 (git 에 안 올라감)
out/<tag>/          재생성 .bdf (테스트 채점 때)
```
