# runs/ — 학습 결과가 쌓이는 곳

## 폴더 구분

| 폴더 | 무엇인가 | 배포하나 |
|---|---|---|
| `train/` | 받은 데이터 **전부**로 학습한 모델. 앱이 쓰는 것 | **O** |
| `validate/` | 성능을 재려고 5-fold 로 돌린 실행. 모델은 버린다 | X |
| `validate/archive/` | 옛 라벨(0721)로 돌린 실험들. 기록용 | X |

**왜 나눠 두나**: 예전에 측정용 fold 모델을 그대로 배포했다가, "이 메쉬를 몇 번 모델이
판정할지"를 실행할 때마다 다시 계산하는 구조가 되었다. 그 계산이 학습 대상 목록의
순서에 의존해서 **PC 마다 다른 답이 나오는 사고**가 났다. 측정과 배포는 섞지 않는다.

앱(`src/app.py`)은 `train/` 만 읽는다. 검증 실행을 보려면 앱의 **개발자 모드**를 켠다.

---

## 이름 규칙

```
cv<라벨버전>_<무엇을 보려는 실험인지>_<조건>[_seed번호]
```

- **`cv`** — cross validation(교차검증). 성능 측정용이라는 뜻이다
- **`0721` / `0918`** — 어느 **라벨 엑셀**로 돌렸는지. **이게 다르면 비교하면 안 된다**
  (0721 → 0918 에서 340개 메쉬의 정답이 바뀌었다. 시험 문제가 다른 것이다)
- **`seed`** — 같은 설정을 난수만 바꿔 반복한 것. 수치가 ±0.002 움직이는 폭을 본다

## train/ — 배포용

이름은 `<역할><라벨버전>` 이다. 라벨 엑셀 파일명에서 버전을 뽑아 자동으로 붙는다.

| 폴더 | 라벨 | 내용 |
|---|---|---|
| `deploy0918` | 0918 | **실제 배포 모델.** 학습 2900 / 평가 전용 323, 8 epoch. `predictions.csv` 포함 |
| `calib0918` | 0918 | 최적 epoch 와 확률 보정 계수를 구하려고 만든 중간 산출물. 배포본 아님 |
| `deploy0721` | 0721 | 라벨 버전 비교용. 같은 절차로 0721 라벨에서 만든 것 |
| `calib0721` | 0721 | 위의 보정용 |

`deploy` 와 `calib` 의 차이:

| | `calib<버전>` | `deploy<버전>` |
|---|---|---|
| 목적 | **최적 epoch·보정 계수 알아내기** | **배포할 모델 만들기** |
| 가중치 학습 | 학습분의 85% | **학습분 전부** |
| 조기종료 검증 | 15% | 없음 (epoch 고정) |
| epoch | 200까지 돌며 알아서 멈춤 | calib 이 알려준 값으로 고정 |
| Platt 보정 | 검증분으로 직접 구함 | calib 것을 그대로 씀 |
| 앱에 보이나 | 아니오 | **예** |

평가 전용 홀드아웃은 둘 다 똑같이 뺀다. 안 그러면 calib 이 epoch 를 고를 때 평가
데이터를 본 셈이 되어 점수가 부풀려진다.

만드는 법: `python scripts/train_deploy.py` (두 단계를 자동으로 돈다)

## validate/ — 0918 라벨 (현재)

| 폴더 | 무엇을 본 실험인가 | AUC |
|---|---|---|
| `cv0918_base` | **현재 설정의 성능.** 보고에 쓰는 숫자 | 0.9823 |
| `cv0918_overfit_ctrl` | 과적합 실험 **대조군** — dropout 0.3 + 조기종료 | 0.9838 |
| `cv0918_overfit_test` | 과적합 실험 **실험군** — dropout 0, 200 epoch, 마지막 가중치 | 0.9734 |

### 과적합 실험이 보여준 것

| | 학습분 AUC | 안 본 조각 AUC |
|---|---|---|
| 대조군(ctrl) | 0.9971 | **0.9838** |
| 실험군(test) | **1.0000** | 0.9734 |

학습 데이터를 완벽히 맞히게 만들면(AUC 1.0000) **안 본 데이터에서는 오히려 나빠진다.**
"학습 데이터는 100% 나와야 하는 것 아닌가"에 대한 답이다.

## validate/archive/ — 0721 라벨 (옛 실험)

**여기 수치를 위의 0918 수치와 나란히 놓고 "좋아졌다"고 하면 안 된다.** 라벨이 바뀌어
채점 기준 자체가 달라졌다.

### 채택된 설정

| 폴더 | 내용 | AUC |
|---|---|---|
| `cv0721_base` | 0721 시절 채택 설정의 성능 (당시 배포본) | 0.9605 |

### 그래프 표현 비교 — 무엇을 노드로 둘 것인가

| 폴더 | 노드 | conv | AUC |
|---|---|---|---|
| `cv0721_graph_elem_gatv2` | **요소** | GATv2 | **0.9602** |
| `cv0721_graph_elem_gine` | 요소 | GINE | 0.9514 |
| `cv0721_graph_node_gatv2` | 절점 | GATv2 | 0.9569 |
| `cv0721_graph_node_gine` | 절점 | GINE | 0.9532 |

→ 요소 기반 + GATv2 채택. 숫자 차이도 있지만, **요소를 바로 지목할 수 있다는 점**이 컸다.

### 쉘/1D 인코더 — 공유할까 나눌까

| 폴더 | 인코더 | 집계피처 | seed | AUC |
|---|---|---|---|---|
| `cv0721_enc_shared_seed0` | 공유 | off | 0 | 0.9610 |
| `cv0721_enc_shared_seed1` | 공유 | off | 1 | 0.9647 |
| `cv0721_enc_shared_seed2` | 공유 | off | 2 | 0.9614 |
| `cv0721_enc_separate_seed1` | **분리** | off | 1 | 0.9586 |
| `cv0721_enc_separate_seed2` | **분리** | off | 2 | 0.9592 |

(분리 seed 0 은 `cv0721_base` 가 같은 설정이다)

**분류 성능은 차이가 없다**(0.958~0.965, seed 변동 폭 안). 그런데도 분리를 택한 이유는
**지목 품질**이다 — 불량 요소 지목 AUC 0.605 → 0.816, top-1 적중 0.300 → 0.496.
분류 정확도만 보고 있었으면 발견하지 못했을 차이다.

### 집계 피처를 넣으면

| 폴더 | 인코더 | 집계피처 | seed | AUC |
|---|---|---|---|---|
| `cv0721_graphfeat_on_seed1` | 공유 | **on** | 1 | 0.9652 |
| `cv0721_graphfeat_on_seed2` | 공유 | **on** | 2 | 0.9580 |

seed 1 과 2 가 0.9652 / 0.9580 으로 크게 흔들린다. **seed 변동 폭 안이라 효과가 있다고
말할 수 없다.** 이런 경우 "두 번 돌려봤더니 결론이 안 난다"가 정직한 결론이다.

## 새 실행 만들기

```bash
python scripts/train_deploy.py                      # 배포 모델 -> train/deploy<버전>
python scripts/run_validation.py --tag cv0918_base  # 성능 측정 -> validate/<tag>
```

`src/train.py` 를 직접 부를 때도 **`--full` 이면 `train/`, 아니면 `validate/`** 로
자동으로 들어간다. `--tag` 를 어떻게 주든 섞이지 않는다.

새 실행에 이름을 붙일 때는 위 규칙을 따른다. **`s2_shr` 처럼 그때의 나만 아는 약자는
쓰지 않는다** — 석 달 뒤의 자신도 모른다.
